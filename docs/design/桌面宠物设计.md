## 0. 一句话定位

**住在桌面壁纸世界里的像素小生命——安静陪伴，偶尔冒泡，替你盯着长任务。**

壁纸是它的世界，宠物是世界的原住民（不是系统附赠的吉祥物）。这是「壁纸引擎 + 宠物引擎」合体的差异化定位：WE 的宠物被压在图标层下，DPET/VPet 没有壁纸世界，本产品同时占两格。

## 2. 架构红线（实现期不可妥协）

1. **宠物是 `pets/` 平级子系统**，不进 session.rs 的 content 体系。理由：pin 层地基是「穿透 + 不可信内容 + 全屏暂停」，宠物每条相反；若做成第五种 content kind，助手会在用户全屏工作时（最需要通知的时刻）睡着。
2. **全屏 = 视觉隐藏 + 通知通路存活**。全屏隐藏期间的职责报信走**系统通知/应用内 toast**（复用 update.rs §4.7 多层通知管线），宠物气泡仅在其可见时作辅助；职责行为任何打扰度档位下必达。
3. **宠物状态输入接口从第一天兼容 pi-pet Protocol v1 消息形状**（wire 消息名沿用，如 `completion_created`）。隐私契约两条：永不传业务内容；**settle ≠ 成功**——桥只表达「停止处理/有新结果」，永不替用户断言任务成败。
4. **素材入库与运行时分离**：精灵包可复用内容库/缩略图管线做管理，但运行时窗口与生命周期归 `pets/` 子系统，两条线不混。
5. **窗口层级契约**：宠物窗 = 非激活 overlay，浮于普通应用窗口之上（always-on-top 族），透明像素逐点穿透（hit mask），不抢焦点；全屏应用出现时整体退场（视觉隐藏，非销毁）。DPI 遵循仓库平台事实：Windows 沿用 pin 层 PMv2 声明与像素对齐要求，macOS 按 Retina backing scale 供图。**层级裁决**：always-on-top（品类默认，pi-pet 同款）——与 Operate 模式的张力用行为规则缓解：闲时活动限定在屏幕底缘「地面带」，中央区域仅交互/报信/久坐提醒时进入（数据规则，无需枚举窗口）；用户可拖至任意位置（尊重显式选择）。多屏收敛**订阅 pin 层 topology_epoch**（复用既有事件源，勿重造轮询——工程笔记明令），事件后按 §7 位置规则钳制。
6. **接入与通信契约**：托盘/设置对宠物的写操作入队 `EngineAction::{PetShow, PetHide, PetSwitch, PetClose}`，由引擎主循环 dispatch 给 `pets::handle_action`（**不经 SessionManager**，与红线 1 呼应）；API.md 动作集随 P1 增补（变更清单见 §4）。宠物窗通信是**双向**通道（壁纸 HostCommand 为单向）：JS→Rust 走 lb-wry IPC handler（点击/拖拽/摸上报），Rust→JS 走 evaluate_script 注入（光标/全屏/空闲事件喂调度器）。窗口 FFI 复用 pin 层 objc2/Win32 绑定基建（FFI 纪律继承工程笔记规则），窗口逻辑归 `pets/pin.rs`。

## 3. 行为模型：状态 × 事件 × 动作（三层分离）

> 架构源自 Shimeji 十五年验证的模式：**动作库存与行为调度完全分离，性格/档位 = 同一库存上的不同频率表**。改玩法 = 改数据，不改代码。

### 3.1 状态层（6 维正交，含启用期）

| 维度 | 取值 | 驱动源 | 启用期 |
|---|---|---|---|
| 心情 | 开心 / 平静 / 无聊 | 互动频率（隐藏心情值 0~100 缓慢衰减，互动回升） | P2（v1 只有互动反应，见 §8） |
| 精神 | 清醒 / 困 / 睡着 | 时间（昼夜）+ 用户空闲检测 | P1 |
| 情境 | 正常 / 躲藏 / 悬空 | 全屏检测 / 拖拽中 | P1 |
| 职责 | 待命 / 盯任务 / 报信 | agent 桥 | P3 |
| 朝向 | v1 简易（左右翻转注视）；16 方向块 v2 | 光标位置 | P1 / v2 |
| 位置带 | v1 仅**地面**；屏边/屏顶 v2+ | 屏幕几何（只用自身坐标系，**不枚举外进程窗口**） | P1 / v2+ |

> 「轻养成」的完整体验 = 基础阶段（P1+P2）合并交付；P1 单独交付时心情系统尚未上线，宠物表现为即时互动反应。

### 3.2 事件层（27 个：基础 22 + agent 5）

> 计数约定：斜杠对（如「空闲开始/结束」）= **单一事件的两个相位**，按 1 个计。基础 22 个在 v1~P2 间启用（光标 feed/空闲/全屏/锁屏/显示器 epoch 均为现成桥能力）；agent 5 个随 P3 桥启用。

| 类别 | 事件（→ 触发行为） |
|---|---|
| 用户输入 | 单击、连点（摸）、摸到头部、摸到身体、戳肚子、拎起、拖动中、被扔、快速划过、右键、长时间对视 |
| 系统 | 开机欢迎（→ 壁纸与托盘就绪后宠物淡入 + wave，壁纸优先加载）、空闲开始/结束、全屏开始/结束、深夜/天亮、显示器变化（→ 按 §7 位置规则收敛）、锁屏（→ 视同空闲，宠物入睡）、久坐触发（P2，→ 走到屏中央敲屏幕 + 气泡提醒） |
| 内部 | 心情跨阈值（P2）、无聊计时到期（P2）、溜达计时到期、睡醒 |
| agent（P3） | 开始工作、工具运行、**有结果（wire: completion_created，语义=停止处理，非成功）**、需要审查、警告 |
| v2+ | 壁纸事件、天气变化、节日 |

### 3.3 动作层（总库存 43 个；**加粗 = P1 交付面 14 个**，其余分期解锁）

| 组 | 动作 |
|---|---|
| 位姿 | **idle 站（含眨眼/张望循环）**、坐、趴、躺、屏边坐晃腿、屏顶倒挂探头、**hide 躲藏退场** |
| 移动 | **walk 走**、小跑、匍匐、跳跃、走向光标坐下看你 |
| 小动作 | **wave 挥手（开机欢迎）**、张望、伸懒腰、打哈欠、挠头、发呆、打喷嚏、追尾巴 |
| 交互反应 | **poked 被点惊跳**、**petted_happy 被摸冒心**、**petted_head 摸头享受**、**poked_belly 戳肚子抗议**、**grabbed_struggle 被拎挣扎**、**thrown_spin 空中翻滚**、**land_bounce 落地弹两下**、**get_up_glare 爬起来瞪你**、被吓炸毛 |
| 睡眠系 | 坐打瞌睡、**sleep_lying 躺睡 ZZZ**、被吵醒迷糊、**wake_stretch 伸懒腰醒** |
| 屏边系 | 走到屏边、抓住屏边、沿屏边爬、屏顶跳下（Shimeji 精髓，仅用屏幕几何） |
| 职责（P3） | 托腮盯任务、任务结果跳、report_wave 报信挥手、需要审查敲屏幕 |
| 彩蛋 | 自我分裂（Shimeji 招牌，愚人节限定频率 ×1）、装死逗你 |

### 3.4 调度模型

```
事件/计时器 → 状态更新 → 【频率表 × 心情修正 × 时段修正】加权随机选动作 → 打断规则 → 播放
打断优先级：被拎 > 被扔 > 职责报信 > 用户点击 > 全屏强制躲藏 > 一切闲时行为
```

- 打扰度三档 = 三张频率表；心情（无聊 ×0.5）与时段（深夜 ×0.3）做乘法修正
- 每动作带冷却时间（防「刚坐下又站起来」抽搐感）；彩蛋动作频率极低，稀缺即惊喜
- **分层归属**：Rust = 窗口 tier + 事件桥（光标/全屏/空闲等原生事件注入）；宠物窗 webview JS = 渲染 + 调度（消费 manifest/频率表数据）。频率表与文案是页面资源，**玩法迭代可不重编译 Rust**
- v1 即启用宠物包自带默认档（`disturbance_default`，安静档）频率表——宠物会低频自主溜达；P2 交付的是三档切换 UI
- 默认参数（数据可调）：调度 tick **100ms**；「连点」判定窗口 **300ms**；动作冷却 **1~5s/动作**；光标注视采样 **200ms** 且仅朝向变化时重渲（保障 §10 的 idle CPU 验收线）

### 3.5 打扰度三档（默认安静）

| 档位 | 溜达频率 | 主动动作 | 气泡频率 |
|---|---|---|---|
| 安静 `quiet`（默认） | 很少挪窝 | 只眨眼、张望 | 几乎不冒泡 |
| 正常 `normal` | 定时溜达 | 偶尔伸懒腰 | 低频 |
| 活泼 `lively` | 频繁走动 | 走到光标附近坐下看你 | 中频 |

## 4. 气泡、菜单与控制面（含 i18n）

**控制面分级**（v1 不留死路）：
- **P1 最小控制**：托盘菜单加宠物组——显示/隐藏宠物、换宠物（两只内置间切换）、关闭宠物（壁纸不受影响）。复用现有托盘基建。
- **P2 工具栏菜单**（VPet 验证过的交互）：点击/右键宠物弹出——设置、打扰度三档、暂时躲开、关闭宠物。

**气泡**：触发式短语——被扔「嗨！」、被摸「♥」、任务有结果「有新结果！」、困了「zZ…」。每只宠物自带文案包（十几条，纯本地）；v1 不做起名、不做对话树。文案包与频率表同层：都是数据文件，加台词 = 改数据。

**i18n（仓库硬惯例：中/英双文案包 + Auto）**：气泡文案按语言分文件（`bubbles.zh.json` / `bubbles.en.json`，manifest 声明引用）；菜单与档位标签进应用 `strings` 双语包，设置页即时切换同样生效。

**视觉契约**：菜单与气泡遵循 [DESIGN.md](DESIGN.md) 的视觉 token；宠物窗是 webview，kit token → CSS 变量的映射在 P0 原型中定稿验证（圆角/描边/双主题）。

**无障碍与安全边界**：彩蛋动作标注低闪烁；reduced-motion 沿用 pi-pet 方案（静态帧 + 静态指示）；宠物窗在系统读屏下标注为装饰性（报信走系统通知，天然可访问）；宠物窗**禁用外部文件拖放**（只做内部拎起拖拽）。

**对冻结规格的变更清单**（P1 开工前落进对应文档，按「改界面先改规格与原型」执行）：① [界面与交互设计.md](界面与交互设计.md) §4.1 托盘菜单增宠物组（显示/隐藏、换宠物、关闭宠物）；② [API.md](../../crates/app/API.md) 动作集增 `Pet*` 四动作（见红线 6）。本文档先行声明 delta。

## 5. 精灵包格式（Gesso 自有格式，spec 草案）

```jsonc
// pet.json —— 单文件清单，跟精灵表同目录
{
  "version": 1,                        // 必填；未知字段：内置宠物宽容跳过，外部导入（v2+）严格 deny_unknown_fields
  "id": "gesso.mochi",                 // 反向域名风格
  "display": "麻薯",                    // 展示名随语言包覆盖
  "disturbance_default": "quiet",      // 该宠物的默认档位（性格 = 默认档 + 文案包 + 走路速度参数）
  "sprite": { "sheet": "sheet.png", "cell": [192, 208], "anchor": "bottom-center" },
  "actions": {                         // 动作 → 帧 映射，行数任意（不学 Codex 固定格）
    "walk":   { "row": 1, "frames": 6, "type": "loop", "move": 24 },
    "poked":  { "row": 3, "frames": 4, "type": "once" },
    "sleep_lying": { "row": 7, "frames": 4, "type": "loop", "overlay": "zzz" }
  },
  "zones": { "head": [0,0,1,0.35], "body": [0,0.35,1,1] },  // 触碰分区（VPet 模式），hit mask 网格上做区域判定
  "bubbles": { "zh": "bubbles.zh.json", "en": "bubbles.en.json" },  // 多语言文案引用
  "directions": { "rows": [9,10], "frames": 16, "optional": true }  // 16 方向注视可选块（v2）；行号由 manifest 声明——本例数值沿用 Codex V2 布局仅为示意，非固定约定
}
```

- `type` 枚举：`loop`（循环）/ `once`（单次回 idle）/ `pose`（位姿保持）——Shimeji 的动作类型学（Stay/Move/Animate/Sequence）裁剪版
- 触碰判定 = **分区（头/身）× 手势（单击=戳 / 连续点=摸）**：头+摸 → petted_head，身+摸 → petted_happy，身+戳 → poked_belly
- 渲染契约补全：sheet 布局 = **单动作一行、每行固定 8 列**（行数任意）；`anchor` = cell 的 bottom-center 对齐窗口底缘中点（地面/行走对齐基准）；`move` = 播放一遍该动作的总位移 px（方向由调度器定）；`once` 播完回退 `idle`；`overlay` = 叠加渲染的第二动作名（上层循环，如 zzz）；动作帧率缺省 **10fps**（可按动作覆写 `fps`），与渲染帧率 30fps 封顶相互独立；`zones` = 相对 cell 的归一化 rect，判定时映射到 hit mask 网格
- hit mask 分辨率：沿用 pi-pet 的 **24×24 采样网格**（`MASK_SAMPLES_PER_EDGE=24`）
- 资源加载边界：宠物包资源走 `gesso://pets/<id>/` **独立命名空间**（与壁纸 library 隔离），宠物窗无 library 访问权
- 信任分级：**内置宽松、外部严格**（外部导入 v2+ 再立，届时移植 pi-pet 导入器的安全全套）
- 首版格式不可能一步到位：`version` 字段第一天就带，格式升级 = 版本号 + 迁移逻辑

## 6. 可迭代性铁律（回答「后续玩法迭代改动大吗」）

1. **代码零硬编码动作名**——渲染器/调度器只认 manifest 映射，加动作 = 素材表加行 + manifest 加条目，不是程序员的事。
2. **玩法 = 数据，引擎 = 代码**——动作库存、频率表、修正系数、气泡文案全部是随精灵包走的数据文件；代码只实现**渲染引擎 / 事件桥 / 窗口引擎**（调度器在宠物窗 webview JS 内，数据驱动，见 §3.4）。

影响面分级：加动作/调玩法/换性格/加台词 = **发素材包，零代码**；加事件源/状态维 = 局部代码（已预留接口位）；同屏多实例/换渲染技术 = 架构级（v1 只预留接口不实现）。「换玩法类型」（如引入经济系统）是产品决策迭代，任何架构不兜底。

## 7. 存档、位置与未来扩展

宠物存档 `pet-save-v1.json`（沿用仓库台账模式：版本化 + 私有权限；**损坏 → 改名备份 + 停止写入 + 保文件待恢复**——exit 78 同款纪律，养成存档丢失比壁纸库更伤用户，禁止任何「解析失败→默认值→回写」链路；v1→v2 迁移逻辑随格式版本单列），字段三层：

- **位置**：`position`（**屏引用 + 相对坐标**：`{ screen: 显示器稳定 ID, x_rel, y_rel }`，**与壁纸指派台账同源**——macOS = `cg-<CGDirectDisplayID>`；工程笔记实测：macOS 26 已删 EDID 三符号探测，EDID hashing 仅是远期升级路径；Windows 用平台对应 ID）——恢复时该屏仍在 → 原样放回；**ID 重编（唤醒/重连）≠ 屏幕消失**：按帧几何一致（±2pt）平移归属（壁纸侧唤醒踩坑的既有解法）；真拔除/未识别 → 钳制到主屏可见区。持久化**借鉴** pi-pet 的归一化 + 越界钳制思路（其实测形态为 monitor.name + 单屏钳制）；屏引用与跨屏拖拽为**本产品新增，P1 实测**。不存裸屏幕坐标（拔屏后落进物理不存在的区域）
- **玩法态**（P2 起使用）：心情值、作息偏移
- **里程碑 metrics**（v1 起就记录，零成本预留）：`adopted_at` 领养时间、`days_together` 陪伴天数、`mood_streak` 连续开心天数、互动分类计数、触发的彩蛋清单

**多显示器行为**（竞品路线：Shimeji 主屏单屏 + 繁殖分身¹ / VPet 手动移动区域² / shimeji-rs·wl_shimeji 统一地面（未核源码）/ mushroom-pet 光标跳屏）：v1 单屏投放——首启主屏，**拖到哪块屏就归属哪块屏**（位置持久化，换屏靠拖拽不另设设置项）；**拖放落点在屏间空隙或屏外 → 立即钳制到最近可见屏**（防「卡两屏中间」）；拓扑变化时按位置规则钳制，不做跨屏漫游。跨屏漫游 v2 另行立项：先「光标屏归属」（>3s 防抖 → 退场动画 → 目标屏淡入，不做跨虚空行走），后「连续漫游」（跨界动画、异 DPI 重算、**错位/断层排列的跳落或钳制——不假设屏排成一行**）；**不做每屏分身**（与「一个生命」叙事冲突，且内存/渲染 ×N 撞 §10 性能红线）；壁纸侧 epoch 两段式收敛语义可参照。

> ¹ Shimeji 源码实况：繁殖行为 `SplitIntoTwo`（上限 50 只）存在，但无任何显示器定向——「每屏分身」是用户手动拖分身的涌现效果，非多屏策略。
> ² VPet wiki 已核实：「移动区域（重置为主屏/设为当前屏幕）」「自定移动范围（拖框）」「智能移动」——无自动跨屏。

**排行榜（远期，需重新立项）**：若做，建议排「陪伴时长/连续打卡」等行为指标而非数值等级（晒陪伴比比数值健康，且无作弊动机）；身份用匿名昵称 + 随机 ID（无账号红线内）；**agent 相关统计永不上榜**（pi-pet 隐私契约延续）；需要接受运营一个轻后端。v2 先做本地成就/里程碑墙（无后端）作为前置。
