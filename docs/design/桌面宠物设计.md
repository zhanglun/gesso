# Gesso 桌面宠物产品设计 v1.0

> 状态：**产品方向与 macOS 实现记录**。
> 本稿记录当前已确认的产品边界和现有实现；世界观、正式角色、美术风格和物种差异化表现仍待《桌面宠物产品与视觉方向决策稿.md》确认，不得把本稿中的探索性设定当成代码硬约束。
> 相关管理窗口视觉 token 见 [DESIGN.md](DESIGN.md)，产品方向决策见 [桌面宠物产品与视觉方向决策稿.md](桌面宠物产品与视觉方向决策稿.md)。

---

## 0. 一句话定位

**一只安静但有生命的现代像素桌面电子宠物——会自己生活，能被摸和戳，也可以在需要时表达简单通知。**

它不是壁纸的一部分，也不是第五种壁纸内容。Gesso 是它的进程宿主；产品上，宠物与壁纸是两个平级、互不影响的能力。

### 0.1 产品关系

- 没有壁纸也可以显示宠物；停止壁纸不影响宠物。
- 用户可以只使用宠物，但退出 Gesso 时宠物随进程退出。
- 宠物是 `pets/` 平级子系统，不进入 `SessionManager` 的 content 体系。
- 用户可以随时隐藏或关闭宠物，不设置死亡、离家出走或惩罚机制。

## 1. 脑爆结论与产品决策

本节记录本轮从零脑爆的结论，作为后续设计和实现的当前事实源。

| # | 决策 | 当前结论 |
|---|---|---|
| D1 | 核心价值 | 首先是好玩的桌面电子宠物；助手能力是增强层，不定义宠物本体。 |
| D2 | 壁纸关系 | 宠物独立于壁纸，不读取壁纸内容，不做壁纸联动；产品上独立、进程上由 Gesso 承载。 |
| D3 | 首发角色 | 第一版不继续锁定猫与果冻组合；现有模板只作程序化占位，首发角色待角色设计重新选择。 |
| D4 | 当前视觉 | 角色视觉特点属于角色设计层，暂不单独锁定宠物风格；管理窗口继续遵循 `DESIGN.md`，当前宠物仅用程序化占位层验证交互。 |
| D5 | 核心互动 | 单击戳；300ms 内连点摸；支持拖拽，不做拎起、投掷和复杂物理互动。 |
| D6 | 自主行为 | 安静但有生命：眨眼、张望、短距离散步、时间+空闲睡觉、闲时低概率彩蛋。 |
| D7 | 活跃度 | 保留安静/正常/活泼三档，全局共用；只影响闲时频率，不影响用户互动和重要事件。 |
| D8 | 轻养成 | 首版只记录陪伴和互动统计，不改变行为，不锁功能，不解锁内容。 |
| D9 | 助手范围 | 首版只做右键菜单触发的模拟事件；不自动捕获系统通知，不接管其他应用通知。 |
| D10 | 通知表现 | `new_result`、`needs_attention`、`warning` 三类；普通气泡约 4 秒，重要气泡约 8 秒，按优先级合并。 |
| D11 | 资源边界 | 首版只使用内置自制或明确授权的物种组件，不支持外部宠物包，不承诺 Codex/pi-pet 格式兼容。个体由图层组件组合生成并在领养时缓存。 |
| D12 | 音效 | 首版完全无音效；声音另行立项并默认可选。 |

### 1.1 明确不做

当前首版不做：

- 壁纸读取或壁纸联动；统一世界观只作为独立桌宠的低曝光背景叙事；
- 自动捕获、拦截、替代微信/QQ/飞书或其他应用的系统通知；
- 系统级通知监听权限；
- 真实 agent / 外部本地通知 IPC；
- 外部宠物导入、Codex V1/V2 或 pi-pet 素材兼容；
- 用户命名、喂食、成长、经济、商店和死亡机制；
- 拎起、投掷、扔下、复杂物理互动；
- 自动避让外部应用窗口；
- 屏边攀爬、屏顶动作、跨屏自动漫游；
- 同屏多实例。

## 2. 角色与视觉

### 2.1 小猫：困倦温柔的首发角色

- 正式名字待视觉稿后确定；当前不锁定“团团”等候选。
- 行为节奏慢，喜欢蜷睡、打哈欠和发呆。
- 平时安静观察，偶尔眨眼、张望、短距离慢走。
- 摸它时眯眼享受；戳它时轻微抗议，不真正生气。
- 气泡短、少、柔和。

### 2.2 果冻生物：亲人撒娇的首发角色

- 正式名字待视觉稿后确定；“泡泡”暂作工作名。
- 行为节奏快，喜欢弹跳、变形和冒泡。
- 更主动回应用户，摸它时反馈明显。
- 通知到来时演出更兴奋，但仍遵守打扰度和打断规则。
- 气泡更主动、更撒娇，但不做长对话。

### 2.3 个体生成与视觉规则

- 用户只从托盘进入首次领养：先选择物种，再进入抽卡式候选流程；每轮展示 3 个彼此不同、由程序基于 root seed 组合人工图层组件生成的同物种个体，确认前可无限 reroll，生成期间按钮短暂冷却，首版不随机物种。生成器的数据结构、版本和缓存边界见《宠物个体生成规格.md》。
- 采用**图层组件组合 + 领养时离线生成并缓存**：人工绘制身体、眼睛、花纹、配色和小特征，程序根据 root seed 从物种模板中选择已验证组件；不创建新的骨骼、动作或玩法能力。
- 物种模板提供经过验证的动作骨架；猫和果冻共享动作语义，但各自使用适合形体的帧和移动方式。
- 首版随机名字、配色、花纹和小特征；不随机生成任意身体结构、骨骼或未经验证的动作。
- 候选只在确认前存在于临时预览；确认后当前个体固定，普通流程不提供重新生成或改养其他物种。每台电脑首版只拥有一个宠物；保存 root seed、正式 `pet_id`、物种、已解析外观参数、中文名和英文名，以及生成器/资源版本；纯数据模型已在 `gesso-core::pet_save` 定义。
- 每轮候选使用不同 root seed 和生成签名去重；新一轮默认不直接复用上一轮候选；中文名和英文名是一一对应的语言对，不在运行时各自随机。root seed 通过命名空间子 seed 派生外观、名字和轻微表现参数，新增尾巴、毛色、衣服等字段不得改变既有字段。
- reroll 不设用户可见次数上限；每次请求只允许一个生成任务在途，生成完成前按钮 disabled，最短冷却目标约 800ms–1s，以实际生成完成时间为准。
- 高级设置提供明确的“重置宠物数据”入口：先隐藏当前宠物，二次确认后删除当前个体、统计、位置和生成缓存，原子写入未领养状态并重新进入首次领养流程；重置不属于日常 reroll，且必须明确提示不可恢复；删除或写入失败时保留原数据。
- 名字在本机存档中查重；内部 ID 使用高熵随机值区分个体。无账号和服务器时，不承诺数学意义上的全球绝对不重名，只承诺个体身份具有极低碰撞概率。
- 两类物种当前只共享通用动作语义；帧序、节奏、表情和短句的差异化表现待产品与视觉方向确认后实现。
- 宠物需要统一但简洁的第一版世界观，v1 最小设定见《宠物世界观·v1最小设定.md》；“缝隙居民”等族群称呼仍待角色设计定稿。
- 它们不属于任何一张壁纸；壁纸是可有可无的桌面背景。
- 宠物颜色固定，不跟随 Gesso 管理窗口的亮暗主题变色。
- 角色文案只在互动、睡觉、彩蛋和通知气泡中出现；不常驻显示名字。
- 首版素材必须为项目自有或明确授权内容，溯源记录遵循仓库资产政策。

## 3. 核心体验循环

```text
启动 Gesso
  → 已领养时，宠物在主屏右下角出现
→ 未领养时，不显示宠物窗口；从托盘点击“开始领养”
  → 安静地眨眼、张望、偶尔走动或睡觉
  → 用户单击戳它，或 300ms 内连点摸它
  → 宠物即时给出有性格的反馈
  → 用户偶尔发现低概率彩蛋
  → 右键打开宠物菜单，调整活跃度、尺寸或查看统计
  → 模拟助手事件到来时，宠物以动作和气泡表达
```

### 3.1 首次领养状态机

首版一台电脑最多拥有一个已领养个体。领养流程与宠物运行状态分开：未领养时不显示宠物窗口，托盘保留“开启宠物/开始领养”入口。

```text
NotAdopted
  └─ 选择物种 → CandidatesVisible

CandidatesVisible
  ├─ reroll → CandidatesVisible（丢弃旧候选，生成 3 个新候选）
  ├─ 选择候选 → CandidateSelected
  └─ 关闭/退出 → NotAdopted（候选不落盘）

CandidateSelected
  ├─ 确认领养 → Persisting
  ├─ 重新选择 → CandidatesVisible
  └─ 关闭/退出 → NotAdopted（候选不落盘）

Persisting
  ├─ 原子写入成功 → Adopted
  └─ 写入失败 → CandidateSelected（保留当前候选，不显示为已领养）

Adopted
  ├─ 显示/启动 → Visible
  ├─ 隐藏/全屏 → Hidden（分别记录临时原因）
  └─ 高级设置重置 → ResetConfirm

ResetConfirm
  ├─ 取消 → Adopted（当前个体和统计不变）
  └─ 确认 → 删除并原子写入空领养状态 → NotAdopted
```

规则：

- 每轮候选必须属于已选物种，三者使用不同 root seed、不同临时 `candidate_id`，并经过生成签名去重；候选只存在内存，不进入正式统计、正式缓存和存档。
- `pet_id` 只在确认领养时创建；候选使用临时 `candidate_id`，被关闭、reroll 或退出丢弃时，不产生正式个体身份。
- `reroll` 只替换当前候选集，不改变物种选择；不设用户可见次数上限。实现只需防止并发重复提交：生成中按钮 disabled，生成完成后恢复；目标冷却约 800ms–1s，不能用固定等待掩盖实际生成耗时。
- 选择候选只改变临时选中态；只有“确认领养”成功完成原子存档后，才创建正式缓存、开始统计和显示宠物；正式存档保存 root seed、已解析外观参数和版本信息，缓存生成失败时优先用已保存参数重建，不改变个体身份。
- 应用在候选阶段退出、崩溃或存档失败：下次回到 `NotAdopted`，不恢复未确认候选；正式宠物不会被半成品覆盖。
- 领养流程不自动弹窗；未领养状态下托盘显示“开始领养”，用户主动进入后才显示物种选择。
- 重置是高级设置中的破坏性操作：先隐藏当前宠物，再二次确认，并明确提醒“当前宠物、统计、位置和生成缓存将被删除，无法恢复”。确认后删除当前个体、统计、位置和生成缓存，原子写入未领养状态。取消或删除失败都保留当前宠物和原存档。
- 首版没有普通“换宠物”入口；未来多宠物升级通过存档版本迁移另行设计。

首版首先验证：**用户是否愿意把它留在桌面上，以及摸戳反馈是否真的好玩。**统计和助手不是用来掩盖核心互动不足的功能。

## 4. 窗口、位置与生命周期

### 4.1 窗口契约

- 宠物窗是非激活 overlay，默认浮在普通应用窗口之上。
- 透明像素逐点穿透，只有可见身体区域响应点击。
- 不抢焦点；右键菜单和轻量面板是独立的可访问 UI。
- 全屏应用出现时宠物整体隐藏，不销毁窗口；退出全屏后自动恢复。
- 不枚举外部应用窗口，也不做自动窗口避让；用户需要时从托盘隐藏。
- Windows 沿用 pin 层 PerMonitorV2 DPI 与像素对齐纪律；macOS 按 Retina backing scale 供图。
- 宠物窗口生命周期归 `pets/`，不调用 `SessionManager` 创建或销毁壁纸窗口。

### 4.2 初始与移动位置

- 首次领养不自动弹出；用户只从托盘进入。选择物种后，每轮展示 3 个彼此不同、随机生成的同物种候选；确认后主屏右下角出现。候选页可返回物种选择；候选不展示内部 seed 或 `pet_id`。
- 用户可拖到任意显示器和任意可见区域。
- 松手后自动钳制到可见工作区；不允许宠物完全跑出屏幕。
- 位置保存为显示器稳定 ID + 屏内相对坐标，不保存裸的跨屏绝对坐标。
- 显示器重配订阅既有 `topology_epoch`；拓扑变化后按当前显示器几何重新钳制。
- 只有一只宠物实例；宠物归属于用户拖放后的那块屏，不自动传送到鼠标所在屏。

### 4.3 隐藏、关闭与恢复

| 状态 | 语义 | 行为 |
|---|---|---|
| 显示 | 正常运行 | 动画、光标注视、互动和可见气泡正常工作。 |
| 隐藏 | 临时退场 | 停止渲染、鼠标观察和普通气泡；从托盘恢复原位置。 |
| 全屏隐藏 | 系统临时退场 | 全屏时自动隐藏，退出全屏恢复原屏幕和位置，不改变用户偏好。 |
| 关闭 | 长期停用 | 停止宠物本体并记住关闭状态；从托盘重新开启。 |

首次启用后默认随 Gesso 启动显示。用户选择关闭后，后续启动继续关闭；用户选择隐藏则视为临时状态。

隐藏期间不累计陪伴时间。首版全屏期间的模拟助手事件直接丢弃，不补发。

## 5. 状态、事件与动作

### 5.1 状态维度

首版只保留对体验有直接价值的维度：

| 维度 | 取值 | 驱动源 |
|---|---|---|
| 精神 | 清醒 / 困 / 睡着 | 时间 + 用户空闲 |
| 情境 | 正常 / 隐藏 / 全屏隐藏 / 拖拽中 | 宠物生命周期与用户动作 |
| 朝向 | 左 / 右（必要时静态注视帧） | 光标相对位置；只看向，不跟随 |
| 活跃档位 | 安静 / 正常 / 活泼 | 用户右键菜单设置，全局共用 |
| 助手提示 | 无 / 新结果 / 需要注意 / 警告 | 首版模拟事件 |

首版没有心情值，不根据互动次数改变行为；统计仅用于展示和未来讨论。

### 5.2 用户事件

- 单击：戳；若当前有通知气泡，同时确认通知。
- 300ms 内连续点击：摸；若当前有通知气泡，同时确认通知。
- 拖动中：移动宠物，不播放普通自主行为。
- 右键：打开宠物菜单/轻量面板。
- 鼠标接近：待机时改变朝向，不主动移动。
- 全屏开始/结束：隐藏/恢复。
- 空闲开始/结束：影响犯困和睡眠概率。
- 显示器拓扑变化：按位置规则重新钳制。

### 5.3 系统/内部事件

- 启动：显示宠物并进入待机；是否播放欢迎动作由素材实现决定，不阻塞核心体验。
- 溜达计时到期：按活跃档位决定是否短距离慢走。
- 犯困计时到期：进入 `sleep`。
- 用户恢复活动或主动互动：从睡眠进入 `wake`，再回到待机。
- 闲时彩蛋计时到期：低概率触发彩蛋，不打断互动和通知。

### 5.4 首版动作语义

每只宠物 10 个动作语义；动作演出和帧数由宠物资源决定：

| 动作 ID | 语义 |
|---|---|
| `idle` | 待机，包含眨眼和张望循环。 |
| `walk` | 当前屏幕内短距离移动；小猫慢走，果冻生物可用弹跳/滑动演出。 |
| `sleep` | 犯困后进入睡眠；小猫蜷睡，果冻生物缩成软塌或漂浮状态。 |
| `wake` | 被用户活动或互动唤醒；包含伸懒腰/弹起等演出。 |
| `poked` | 单击戳的即时反馈。 |
| `petted` | 连点摸的即时反馈。 |
| `notify_result` | 新结果：抬头、挥手或轻庆祝。 |
| `notify_attention` | 需要注意：敲屏幕或其他明显提醒。 |
| `notify_warning` | 警告：警觉、炸毛、变色等明显但低闪烁的演出。 |
| `hide` | 隐藏/恢复时的退场或入场演出。 |

`idle`、`sleep`、`wake` 内部可以包含多个小动作，不必为每个小动作增加独立 manifest 动作名。

### 5.5 调度和打断

```text
事件/计时器
  → 更新状态
  → 按活跃档位选择自主行为
  → 检查动作冷却与打断优先级
  → 播放动作和气泡
```

打断优先级：

```text
warning / needs_attention
  > 用户摸戳
  > new_result
  > 全屏强制隐藏
  > 自主行为 / 彩蛋
```

规则：

- 重要事件可以打断睡觉或走动；当前 macOS 基础实现已支持鼠标接近/移动和显示恢复唤醒睡眠状态。
- `new_result` 等普通事件等待当前动作结束；短时间多条按优先级合并。
- 彩蛋只在闲时触发，不打断互动和通知。
- 安静/正常/活泼只调整自主动作和普通气泡频率，不调低用户互动和重要事件。
- 默认参数沿用当前验证方向：宠物行为调度 tick 150ms、连点窗口 300ms、动作冷却 1~5s、光标观察约 200ms；Watching 根据光标在宠物窗口内的左右位置做轻微朝向反馈。

### 5.6 活跃档位

| 档位 | 自主移动 | 自主动作用 | 普通气泡 |
|---|---|---|---|
| 安静 `quiet`（默认） | 很少短距离移动 | 眨眼、张望、偶尔睡觉 | 几乎不冒泡 |
| 正常 `normal` | 定时短距离移动 | 偶尔伸懒腰等 | 低频 |
| 活泼 `lively` | 更频繁移动 | 更容易做主动小动作 | 中频 |

## 6. 气泡、模拟助手与菜单

### 6.1 气泡

- 气泡显示在宠物旁，不常驻名字。
- 小猫和果冻生物的短句风格不同，但事件语义保持一致。
- 普通气泡约 4 秒；重要气泡约 8 秒。
- 点击宠物后当前气泡消失，并记录一次确认。
- 内容只在内存中短暂存在，不保存通知历史。
- reduced-motion 下使用静态帧和静态提示，不依赖闪烁。

### 6.2 模拟助手事件

首版从宠物右键菜单的开发项触发，不开放真实外部接口：

```json
{
  "type": "new_result | needs_attention | warning",
  "title": "短标题",
  "summary": "短摘要"
}
```

事件内容由模拟入口提供，宠物根据角色包装。首版所有事件只做宠物动作和气泡，**不发送系统通知**。

- `new_result`：普通事件，当前动作结束后提示。
- `needs_attention`：重要事件，可打断当前动作。
- `warning`：重要事件，可打断当前动作并使用更明显演出。
- 多条事件按优先级合并；普通结果可合并为数量提示。
- 全屏时宠物不可见，模拟事件直接丢弃。

真实本地接口、agent bridge、系统通知和外部应用通知替代另行立项，不以本稿作为承诺。

### 6.3 右键菜单与轻量面板

右键宠物打开菜单/轻量浮层，包含：

- 安静 / 正常 / 活泼；
- 小 / 中 / 大；
- 查看当前宠物的陪伴和互动统计；
- 隐藏；
- 关闭；
- 模拟助手事件（开发入口）；
- 打开设置；
- 高级设置中的“重置宠物数据”（不放在右键快捷菜单）。

托盘提供“显示宠物/开启宠物/管理宠物”入口，保证隐藏或关闭后仍然可恢复。

菜单、面板和通知文字支持键盘与读屏；宠物动画本身标注为装饰性内容。

## 7. 尺寸、显示和无障碍

- 提供小 / 中 / 大三档尺寸，默认中等尺寸。
- 优先保持整数像素缩放，避免像素模糊。
- 默认无音效，首版不加载音频资源。
- 只有可见像素响应鼠标，透明区域逐点穿透。
- 禁止外部文件拖放；拖拽仅用于移动宠物本身。
- 彩蛋和警告动作遵守低闪烁约束。
- 系统 reduced-motion 下停用连续动画，显示静态帧和静态提示。

## 8. 统计与存档

### 8.1 统计

首版只记录当前唯一宠物：

- 陪伴天数；
- 摸次数；
- 戳次数。

陪伴时间只在宠物可见且运行时累计；隐藏、关闭和全屏隐藏期间不累计。统计不影响宠物行为，不解锁功能，也不改变活跃度。

### 8.2 存档

继续沿用版本化私有存档纪律，建议文件名 `pet-save-v1.json`。首版根结构为单个领养槽，但保留 `version` 和 `adoption` 容器，为未来多宠物迁移预留空间：

- `adoption`: `null`（未领养）或一个已确认的个体；
- 个体名称保存为成对的 `name.zh` / `name.en`，两者表达同一个名字，不在运行时各自随机；
- 位置：显示器稳定 ID + 屏内相对坐标；
- 当前宠物：当前已领养的唯一物种个体；
- 全局活跃档位和尺寸档位；
- 显示/关闭偏好；
- 当前宠物的陪伴与互动统计；
- 重置状态（仅通过高级设置，需二次确认）；
- 存档容器保留版本字段，为未来多宠物升级预留迁移空间。

存档损坏时：改名备份、停止写入、保留原文件待恢复；禁止“解析失败 → 默认值 → 回写”覆盖用户数据。

## 9. 资源与实现边界

### 9.1 首版资源

- 首版保留程序化物种模板接口；具体首发角色待角色设计确认，首次领养只能从托盘主动进入；
- 生成器先以占位组件和确定性测试数据落地，再替换正式美术资源；
- 使用自制或明确授权的身体、动作和装饰组件；
- 领养时按 seed 组合并缓存一个个体；
- 每台电脑首版只拥有一个宠物：首次只选择一个物种，每轮展示 3 个候选，确认前可无限 reroll；确认后固定当前个体，普通流程不提供重新生成或改养其他物种；高级设置可在二次确认后重置全部宠物数据并重新领养；未来多宠物升级另行设计迁移。
- 不开放外部导入；
- 不承诺 Codex V1/V2、pi-pet 或其他第三方格式兼容。

内部资源仍可使用版本化 manifest，但不应为了未来外部导入提前实现完整信任分级、导入器或兼容层。

### 9.2 分层

- Rust：窗口 tier、平台事件、位置存档、显示器 topology、生命周期和 IPC 边界。
- 宠物 WebView：精灵渲染、动作播放、气泡和数据驱动调度。
- `pets/` 独立于壁纸 `SessionManager`；不把宠物注册成 `WallpaperKind`。
- UI/托盘写操作入队 `EngineAction`，由主循环 dispatch 给宠物子系统；不由 UI 直接创建或销毁原生宠物窗口。
- 宠物资源若使用自定义协议，应保持 `gesso://pets/<id>/` 与壁纸 library 隔离。

## 11. 验收标准与风险

| 项 | 验收线 |
|---|---|
| 核心互动 | 单击稳定判定为戳；300ms 连点稳定判定为摸；点击不穿透可见身体，透明区域可穿透。 |
| 窗口 | 非激活、always-on-top、可拖拽、可隐藏；全屏隐藏后能恢复原位置。 |
| 位置 | 主屏右下角首启；跨屏拖放后能保存并在拓扑变化后钳制到可见区。 |
| 行为 | 安静档 idle CPU ≤ 1% 单核目标；动画帧率封顶 30fps；睡眠和隐藏期间不持续渲染。 |
| 资源 | 宠物子系统增量内存目标 ≤ 150MB；内置物种组件无外部网络和外部文件访问；领养个体可从 seed 稳定重建。 |
| 可访问性 | 菜单和气泡可键盘操作/读屏；reduced-motion 不依赖连续动画或高频闪烁。 |
| 助手 | 三类模拟事件动作正确；重要事件能打断；普通事件按优先级合并；全屏期间不补发。 |
| 数据 | 统计仅属于当前唯一宠物；存档损坏保文件、不默认覆盖；不持久化通知正文；重置操作明确提醒、二次确认且不可恢复；缓存失败可由同一 seed 重建。 |

主要风险：

1. 两类物种 × 10 个语义动作仍有较高美术成本；首版只有一个已领养个体，应先用占位精灵验证三候选抽卡、无限 reroll、生成中保护、领养确认和图层组合生成。
2. always-on-top 会偶尔遮挡内容；首版接受用户从托盘隐藏，不做外部窗口避让。
3. Windows 透明、置顶、逐点穿透和非激活组合不属于本轮 macOS 交付，后续 Windows 宠物窗口阶段单独验证。
4. “好玩”不能由统计和助手功能替代；核心摸戳反馈必须先通过原型验证。
5. 真实通知接入与系统通知替代不属于当前首版，未来必须单独验证平台权限、隐私和失败恢复。
