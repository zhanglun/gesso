# 桌面宠物产品与视觉方向决策稿

> 状态：**方向已确认，角色与视觉仍待设计**。
> 本稿用于约束近期实现边界。产品方向和技术边界已确认，但世界观只做第一版最小设定，正式角色、美术风格和资源方案仍待后续设计，不得提前固化进状态机或存档契约。

## 1. 当前产品定位

桌面宠物是 Gesso 中独立于壁纸的轻量陪伴能力，核心是**安静陪伴 + 轻游戏**。它是一个可以被发现、摸戳、观察和偶尔调整的桌面角色；助手提示只是可选增强，不承担通知中心或生产力工具的职责。

### 当前确认

- 宠物窗口独立于 GPUI、壁纸窗口和 `SessionManager`。
- 宠物不读取壁纸、不依赖壁纸，也不进入用户工作窗口。
- 首版只支持一只宠物；支持领养、隐藏、拖动、摸戳、观察、统计和基础设置。
- 产品理由就是“好玩”：不强行把宠物包装成生产力或通知能力。
- 用户与宠物的关系是“被用户领养的陪伴伙伴”：用户选择并陪伴它，但不承担日常照顾义务。
- 不做死亡、饥饿、惩罚、经济、复杂物理、自动避让和全局鼠标监听。
- 所有写操作继续经 `EngineAction`，状态机继续由 `gesso-core` 持有。

## 2. 当前体验基调

当前锁定“安静陪伴 + 轻游戏”，并以克制但有生命为表现标准；不提前锁定具体角色性格：

- 宠物应该安静存在，不持续抢夺注意力。
- 主动回应保持极低频，主要回应用户直接互动和少量明确状态。
- 用户主动互动必须即时、稳定、可理解。
- 轻游戏先包含摸戳反馈、发现自主行为和未来的短暂陪玩；第一版暂不定义具体小游戏。
- 自主行为以短反馈为主，不做长时间自动表演。
- 陪伴感来自安静存在、偶尔回应，以及本机保存的共同经历记录。
- reduced-motion 下仍保留静态的状态差异。

## 3. 已确认与暂不锁定的方向

### 已确认

- 第一版需要一个统一的小型设定集；宠物来自“数字缝隙”，先解释它为什么能出现在桌面上，再用少量规则支撑产品体验。v1 最小设定见《宠物世界观·v1最小设定.md》。
- 核心世界规则：宠物不打扰工作、不会因缺少互动而死亡或消失、会感知时间，并且只属于这台电脑。
- 第一版不继续锁定“猫 + 果冻”作为首发组合；现有两类模板保留为技术占位，后续可删除或替换。
- 首发先做一个无物种的中性小生命，不提前绑定猫、果冻或其他现实物种；形态方向已确认为拟物小蜡烛（从现实物件衍生，火苗保留暖光灵魂），见《小蜡烛·角色设计方向.md》。
- 个体继续采用程序化组合：从经过审核的组件池中按稳定 seed 选择外观，不由程序生成未经验证的结构。
- 角色特点属于角色设计层；角色的视觉风格、性格和动作特点不能反向固化通用状态机。

### 暂不锁定

- 世界观的正式名称、术语、起源细节和完整设定集内容。
- 小蜡烛的渲染风格（像素、软胶、扁平、手绘、几何等）；正式名字、色值、蜡身比例和帧表待视觉基准图。
- 正式资源的颗粒、动作帧表和气泡文案。
- 是否保留候选抽卡、无限 reroll 和完整资源缓存作为最终首版流程。
- 第一版具体短暂小游戏；在摸戳和发现行为完成前不进入实现。

现有《缝隙宇宙·世界观设定集》和《首发宠物角色与文案》降级为探索材料；后续角色设计确认后再决定是否继续沿用。

## 4. 对代码的约束

在方向确认前：

- `PetBehaviorState` 只表达通用行为语义：Idle、Watching、Walking、Sleeping、Poked、Touched、Dragging。
- AppKit 层只提供中性占位反馈，不写入猫或果冻专属动作分支。
- 资源接口应允许静态占位图、正式静态资源和正式动画资源逐步替换。
- 生成器只保存稳定身份和外观参数，不把未确认的风格字段扩散到存档契约。
- 不为未来世界观预留未经验证的通知、成长、社交或外部 agent 抽象。

## 5. 下一阶段

先完成一个中性小生命的通用体验：

1. 继续打磨领养、显示/隐藏、拖动、摸戳、观察、睡眠和唤醒。
2. 保留极低频自主行为，避免主动打扰。
3. 记录本机陪伴时间和互动次数等共同经历。
4. 为未来短暂小游戏保留产品位置，但暂不实现具体玩法。
5. 在不锁定视觉风格的前提下，定义程序化组件池和资源接口的最小契约。
6. 后续再单独设计中性小生命的外观、性格和世界观细节。

在角色和视觉设计确认前，工程不做物种差异化与正式美术绑定。
