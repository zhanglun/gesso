# 宠物助手事件接口选型（P3 立项文档）

> 状态：**v1.0，已评审冻结（2026-10-25 四项拍板，结论见 §7）**。本文档回答「外部进程如何把事件送进宠物」，是 P3 接口线格式定稿的前置交付物。
> 事实源关系：分流规则见《界面与交互设计.md》§3.1；产品边界与 P3 前置见《桌面宠物设计.md》（D9、v1.1 修订）。

---

## 1. 问题与范围

- **谁在发**：本机进程——用户自己的 agent 程序、脚本、未来可配合的第三方应用。
- **发什么**：三个语义档位（复用 `PetNotice`），**不是消息文本**（宠物稿 v1.1 前置：type-not-text）。
- **送给谁**：宠物行为状态机（气泡），不是系统通知面（分流规则 §3.1：宠物气泡只承载氛围类与无动作回声）。
- **明确不做**（冻结项，不因本文档重开）：系统级通知捕获/拦截/替代；自由文本；跨机/远程源；离线排队补发。

## 2. 威胁模型与认证（P3 前置①，先于线格式）

### 2.1 防不了什么（先说清，避免伪安全感）

同用户恶意软件**不可防**：它已拥有会话，可以读写所有用户文件、注入进程、模拟输入——任何本机认证对它都是摆设。认证设计不以此为目标。

### 2.2 真实要防的三件事

1. **误发与滥发**：集成方 bug、失控脚本把事件当日志刷——宠物变神经质，违背「安静但有生命」定位。
2. **跨用户会话注入**：同机其他用户会话/降权上下文的进程不应能触碰。
3. **借宠物之口的社工诱导**：宠物是被信任的可爱界面；外部若能驱动 `Warning` 档（「这个不太对」+ 警觉演出），可配合其他欺骗手段放大说服力。

### 2.3 分层对策（自下而上，前两层零成本）

| 层 | 对策 | 抵御 | 状态 |
|---|---|---|---|
| L1 | 传输绑定当前用户（UDS 放用户目录 / 命名管道默认 ACL） | 跨用户会话注入 | 随传输免费获得 |
| L2 | type-not-text：只收枚举档位，文案本地模板生成 | 内容级注入（把攻击面从「任意文本」压到「三选一」） | **已冻结**（宠物稿 v1.1） |
| L3 | 逐源 opt-in 名单 + 首次连接确认 | 误接/未授权接入、社工档位滥用 | **已拍板**：首连弹窗 + 设置页管理（v1 交付） |
| L4 | 状态机同类 60s 冷却（`69244f8` 已上线）+ 连接级限速断连 | 洪泛残余 | 冷却已上线；限速随 v1 |

### 2.4 认证模型推荐（v1 姿态）

**L1 + L2 + L3，不引入 token。** 理由记录：

- Token 对同用户威胁无效（同用户可读 token 文件），对跨用户威胁 L1 已覆盖——引入只增加集成方接入成本，不改变安全边界。
- 源身份 v1 采用**自我声明名**（payload `src` 字段，类似 User-Agent），用于确认弹窗展示与名单匹配。已知可被同用户进程冒名——在「防误发、防社工」的目标下可接受；若未来要防冒名，升级路径是校验进程可执行路径（procfs/Win32 QueryFullProcessImageName），接口不变、名单键从名字换成路径指纹。

## 3. 传输选型

| 方案 | 平台接缝 | 误发现/误用 | 实现量 | 反馈通路 | 评估 |
|---|---|---|---|---|---|
| **命名管道(Win) / UDS(mac)** | 2 个薄平台面（放 `bridge/`，与 `pin/` 同纪律） | 无端口可扫；名字固定不可猜 | 小 | 有（同连接回包） | **推荐** |
| 回环 HTTP | 1（跨平台统一） | 端口可被本机进程扫描发现（有先例：`protocol.rs` 媒体服务绑 `127.0.0.1:0`，凭据=不可猜 id；事件口没有「不可猜」天然凭据，需靠 L3 补） | 小（有现成先例） | 有 | 备选 |
| CLI 直调 | — | — | — | — | **不是传输**：单实例锁下 CLI 仍需 IPC 到主实例；定位为后续薄客户端 |
| 文件投递（watched dir） | 1 | 轮询、竞态、无反馈 | 小 | 无 | 否决 |
| WebSocket | 1 | 同 HTTP | 中 | 有 | 否决（对单机单向事件是过度设计） |

**推荐**：命名管道 / UDS。理由：事件口与媒体口信任模型不同——媒体口的「不可猜 id」凭据不适用于「谁都能试着发一条」的写入语义，管道/UDS 的连接即用户上下文凭据，天然少一层。接入成本（连接字符串 vs URL）对集成方相当。

## 4. 线格式（v1，**已冻结**）

请求（一行 JSON + `\n`）：

```json
{"v":1,"kind":"new_result","src":"my-agent"}
```

- `kind` ∈ `new_result | needs_attention | warning`，与内部 `PetNotice` 三档一一对应。语义即产品语义（「有新动静 / 你要看一下吗 / 嗯……这个不太对」），不另设抽象层；未来若需要更细的外部语义（如 `task_done`），扩枚举 + 加映射表，线格式版本号已预留。
- `src` 必填，自我声明名，确认弹窗与名单用。
- **无 `text` 字段**——这是冻结约束不是省略；文本随逐源授权白名单机制放开（宠物稿 v1.1）。

响应（一行 JSON）：

```json
{"ok":true}
```

错误：`{"err":"unauthorized"}`（源不在名单且未被确认）/ `unknown-kind` / `rate-limited`（连接级限速触发，随即断连）。

**实现注记（S1 落地，2026-10-25，`gesso-core::pet_events`）**：
- 错误码补齐 `bad-request`——JSON 不合法/非对象/字段缺失或类型错/版本非 1/src 非法都归此类（原文错误列表未覆盖畸形行，此为实现澄清非线格式变更）。
- **未知字段一律拒绝**（恰三字段，多一个即 bad-request）——type-not-text 的纵深防御：携带 text 的行在解析器即拒，不依赖发送方自律。
- 行尾单个 `\r` 容忍（CRLF 归一化），其余严格；`kind` 非字符串归 bad-request，字符串但不在档位内归 unknown-kind。解析器 + 8 项单测全绿。

## 5. 失败与恢复

- **应用未运行**：连接拒绝。客户端 fail-fast，不重试不排队——宠物事件是即时氛围，离线补发违背「全屏期间不补发」的同一产品判断。
- **非法输入**：立即断连，不解析不猜。
- **洪泛**：连接级限速（建议 6 次/分/源，超出断连）+ 状态机 60s 同类冷却吸收穿透者（已上线）。
- **名单存储**：`settings.json` 新组；重置宠物数据时**一并清空**（已拍板，见 §7.4）。

## 6. 与现有架构的对接（实现预览，非本文档范围）

- 监听线程常驻 `bridge/`（`pet_events_unix.rs` / `pet_events_windows.rs`），收到合法事件 → `engine::enqueue(EngineAction::PetBehavior(Notify(kind)))`——与 `update.rs` 回声、`GESSO_PET_NOTICE` 钩子同一条已验证通道，窗口层零改动。
- 接入点在冷却之后、显示之前全部复用现有状态机语义（优先级合并、睡眠过滤、拖拽丢弃）。「全屏期间不补发」由构造保证（无离线队列即无补发）；全屏期间气泡是否可见随各平台窗口策略——Windows 宠物窗全屏自动隐藏（不显示），macOS 宠物窗 FullScreenAuxiliary 常驻全屏空间（气泡随宠物可见，既有设计）。

## 7. 评审结论（2026-10-25 拍板）

1. **opt-in UX**：首连弹窗 + 设置页管理——陌生源首次连接时弹确认（「应用 X 想给宠物发事件」），批准/拒绝；设置页提供已授权名单的查看与撤销。
2. **源身份**：自我声明名（payload `src`，类似 User-Agent）；exe 路径校验不进 v1，留作 §2.4 升级路径。
3. **CLI**：随 v1 交付——`gesso-pet-notify <kind>` 一行接入，客户端约 50 行（连管道 → 发一行 JSON → 读回包 → 退出码）。
4. **重置语义**：重置宠物数据时一并清空事件源名单——「重置全部宠物数据」语义完整，对转手/交接场景保守。

## 8. 实施切片（评审后另立分支，此处仅排序）

S1 协议常量 + 行解析器（`gesso-core::pet_events`，✅ 2026-10-25）→ S2 监听线程 + enqueue（✅ 2026-10-25：`bridge/pet_events{,_windows,_unix}`，Win 命名管道 `\.\pipe\gesso-pet-events` + FILE_FLAG_FIRST_PIPE_INSTANCE 单实例持有，mac UDS $TMPDIR + 0600；本机三行冒烟全过——合法/走私/未知档位，同连接多行复用）→ S3 opt-in 名单 + 首连确认弹窗 + 设置页管理 → S4 CLI 客户端（已确认随 v1，复用 `PetEventRequest::to_line`）。
