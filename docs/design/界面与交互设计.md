# Gesso 界面与交互设计规格 v1.0

> 模式：**Operate**（工具服务于任务，界面消失于任务）。配套：[PRODUCT.md](PRODUCT.md) · [技术方案.md](技术方案.md) §3.7/§3.8
> 用户决策（2026-02）：轻量工具定位 · 中文默认+i18n 预留 · 跟随系统双主题 · 托盘常驻

## 0. 设计立场

**糙感检查**：壁纸工具的失败模式不是平淡，而是"每个控件都微妙地不对劲"。用过 WE/Lively/Raycast 的用户应该第一眼就信任每个控件——工具退到壁纸后面。

**工艺基准**（craft bar，建议值，可在确认轮修正）：Raycast 的面板纪律 + Linear 的密度与键盘 + 系统设置的双主题克制。**低于此基准的细节不许出厂。**

**反目标（v1 明确不做）**：标签系统、收藏夹、轮换播放列表、批量多选管理、向导跳过后的反复骚扰、模态优先、装饰性动效。轻量是定位不是妥协。

## 1. 视觉世界（已锁定）

**世界**：跟随系统的原生专业工具。中性灰阶为骨，单一强调色只做三件事——主操作、当前选中、状态指示。壁纸预览（全饱和、动态）是画面里唯一的彩色，**界面越安静，壁纸越出彩**——这是本产品视觉的底层逻辑。

### 1.1 语义色（双主题各一套 token，值在实现时以系统灰阶校准）

| Token（语义） | 亮色基准 | 暗色基准 | 用途 |
|---|---|---|---|
| `bg/surface` | 白 #FFFFFF | #1E1E20 | 内容区底 |
| `bg/panel` | #F5F5F7 | #26262A | 侧栏 / 工具条 |
| `bg/elevated` | #FFFFFF + 阴影 | #303034 | 弹出菜单 / 下拉 |
| `text/primary` | #1D1D1F | #EBEBED | 主文本 |
| `text/secondary` | #6E6E73 | #9B9BA1 | 次文本 / meta |
| `accent` | #316EF5（系统蓝系） | #5B8DEF | 主操作 / 选中 / 状态 |
| `accent/soft` | 蓝 12% 透明度 | 蓝 18% | 选中底、悬停底 |
| `danger` | #D33A3A | #E5545B | 失效 / 破坏性操作 |
| `border/hairline` | #E5E5EA | #3A3A3F | 1px 分隔线 |

规则：**强调色禁止用于装饰**。危险红只表达真实故障（素材失效），不用于确认按钮。

### 1.2 排版

- **单一 sans 家族，系统栈**：macOS = SF Pro（GPUI 默认即系统字）；Windows = Segoe UI Variable。不引入自定义字体——原生工具的字体即身份。
- 固定字号阶梯（比例 1.16）：`12`（meta/角标）、`13`（正文/控件，**基准**）、`15`（区块标题）、`20`（页面标题，仅向导用）、`28`（仅向导欢迎页一句话）。
- 数字等宽变体（tabular figures）用于 FPS、时长、分辨率。

### 1.3 图标

线性、单色、1.5px 描边、圆角端点，16px（行内）与 20px（工具条）两档。**不用 emoji**。播放/暂停/显示器/设置等标准件直接采系统意象（不逐像素复制系统图标，但语义与视觉重量对齐）。

### 1.4 动效纪律

150–250ms，`ease-out`。动效只表达状态变更：面板展开、指派切换时缩略图淡入、暂停指示出现。**禁止**：页面加载编排、壁纸卡片的装饰性循环动画、非状态性的任何弹跳。

## 2. 窗口模型与信息架构

```text
┌ 托盘（常驻，产品真正的主界面）
│   左键 / 右键 → 原生菜单（暂停 / 随机换一张 / 管理窗口 / 自启 / 退出）
│
└ 管理窗口（880×600 默认，420–1100px 自适应，关闭=隐藏）
    顶栏：产品名 + 三页签（壁纸库 · 显示器 · 设置） + 窗口控制
    │
    ├ 壁纸库（默认页）
    ├ 显示器
    └ 设置
```

- 三页签而非侧栏：轻量定位下只有三个目的地，页签少一次认知跳转。
- 主窗口最窄 420px 时页签退化为图标。

> **2026-10-11 变更（壁纸窗可见性语义，v3 定稿）**：显示器重配（唤醒/解锁/插拔/改分辨率/主屏切换/合盖开盖）期间，不变量是「**可见的壁纸窗必须与当前拓扑一致**」：几何未变的屏保持旧画面继续播放；几何已过时（显示器模式切换/重锚/移除）的窗口在事件后 ~30ms 内熄灭，由桥接静态帧兜底，拓扑跨采样稳定后以原子切换施加新几何并点亮（新接入屏 ≈2s）。过渡几何（半程枚举的小窗/超大帧/放大裁切）从构造上不可见。

> **2026-10-11 变更（桌面桥接，用户决策：默认开 + 托盘逃生门）**：重配期的「短暂消失」里露出的是系统桌面壁纸——Gesso 运行期间把它接管为**当前壁纸的静态帧**（视频取首帧全分辨率 / 图片拷贝 / shader·html 用缩略图档），过渡即无缝；**退出、取消指派、关闭开关时恢复用户原壁纸**，托盘常驻「恢复系统壁纸」逃生门。代价与边界（设置页文案如实告知）：运行期间系统设置 > 墙纸显示的是静帧；SIGKILL/断电来不及恢复，残留由下次启动对账修复；用户运行期间手改壁纸的，Gesso 绝不覆盖（按「桌面图是否仍是我们的桥接帧」判定）。

## 3. 全局组件规格

每个交互组件六态齐全：**default / hover / focus / active / disabled / selected**（+ 上下文态 loading / error）。同一动词在所有页签里长一样。

| 组件 | 规格 |
|---|---|
| **按钮** | 高 28px（紧凑 24px）。主按钮 = accent 实底白字；次按钮 = panel 底 + hairline 边；文字按钮 = 无底。圆角 6px |
| **开关** | 系统开关规格（36×20），状态色 = accent |
| **下拉** | 28px 高，右侧 chevron，展开 elevated 底 + 阴影，键盘 ↑↓↵ |
| **输入框** | 28px，focus = accent 1.5px 外描边（不发光） |
| **右键菜单** | elevated 底，8px 圆角，阴影，分隔线分组；破坏项红字置底 |
| **卡片** | 见 §4.3 卡片解剖 |
| **角标** | 11px 等宽大写，如 `VIDEO` `WE`，hairline 描边胶囊 |
| **气泡通知** | 托盘气泡：标题 + 一行正文 + 一个动作链接，5s 自动消失；同类故障 60s 内去重 |

**键盘模型**（管理窗口）：
- `Tab` 走焦点环（focus 环 2px accent，永远可见，不尊重"focus-visible 折叠"——工具类应用键盘是公民）
- `←/→` 或 `1/2/3` 切页签；`F` 聚焦搜索；`Esc` 关闭弹出层
- 库网格：方向键移动、`↵` = 设为主显示器、`Space` = 悬停预览定格
- `Cmd/Ctrl+,` → 设置页（工具惯例）

### 3.1 通知面与分流（v1.1 新增）

应用的通知面共四个：**系统通知**（macOS osascript / Windows WinRT toast）、**应用内 toast**、**托盘气泡 / tooltip**、**宠物气泡**（桌面宠物，见 §4.8 与《桌面宠物设计.md》）。产生通知的功能按事件三分类接入下表路由，不逐功能自定。

| 类别 | 定义 | 例 |
|---|---|---|
| **可行动** | 需要用户操作才有后续 | 更新可下载、导入失败需处理 |
| **警告** | 出错但可忽略或自愈 | 下载中断（可重试）、缩略图生成失败 |
| **氛围** | 无需操作的确认/里程碑/社交性事件 | 导入完成、陪伴里程碑、彩蛋 |

**分流规则：**

1. **事实源原则**：可行动事件以系统通知 + 应用内 toast + 托盘为事实源（持久或常驻）。宠物气泡 4s/8s 即逝且不存通知历史（宠物稿验收线），**不得作为可行动事件的唯一承载**。
2. **宠物气泡只承载氛围类事件**，以及可行动事件的无动作「回声」——仅文案提及、不带动作链接，同一事件一次发生内至多一次。
3. **跨面去重**：同一事件一次发生内，跨面合计打扰 ≤ 1 次事实源承载（可行动事件的持久面，或氛围事件的当下可见确认——如导入完成的应用内 toast）+ 1 次氛围回声；「同类故障 60s 内去重」（本节气泡通知行）扩展为跨面通用规则。
4. **宠物气泡同类冷却**：同类通知 60s 内不重复，由宠物行为状态机在入口处合并（此前只有并发优先级合并，无时序冷却）。
5. **全屏不补发**沿用宠物稿 §11 验收线；系统通知/toast/托盘各层独立、互不阻塞（§4.7）。

**平台约束**：系统通知全线 best-effort，不视为可靠通道——Windows toast 依赖 WinRT + AUMID（安装版已注册；便携版未注册 AUMID 预期失败；精简系统 WinRT 运行时可能缺失），失败静默降级到托盘/应用内通道。

### 4.3 壁纸库页（默认页）

```text
┌──────────────────────────────────────────────────────┐
│ Gesso   [壁纸库] [显示器] [设置]                 – □ ✕ │ ← 顶栏 44px
├──────────────────────────────────────────────────────┤
│ [全部|视频|动图|图片|Shader|网页|WE]  🔍搜索___ [+导入▾] │ ← 工具条 48px（图片分类 2026-10 M6 新增）│
├──────────────────────────────────────────────────────┤
│ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐          │
│ │ 预览区  │ │        │ │        │ │        │          │ ← 卡片：响应式等分
│ │        │ │        │ │        │ │        │          │   minmax(196px,1fr)，
│ ├────────┤ ├────────┤ ├────────┤ ├────────┤          │   列数随窗口宽度适配、
│ │▐nebula ▸│ │waves   │ │clock   │ │sakura WE│         │   撑满整行不留尾空
│ │VIDEO 4K│ │SHADER  │ │WEB     │ │WE·VIDEO│          │   (16:9 预览+56px 信息条)
│ └────────┘ └────────┘ └────────┘ └────────┘          │
│      …（滚动）                                         │
├──────────────────────────────────────────────────────┤
│ 128 项 · WE 34 · 双击设为主显示器 · 拖入文件导入          │ ← 状态条 28px
└──────────────────────────────────────────────────────┘
```

**卡片解剖**（信息条 56px）：
- **网格响应式**（原型 `.wall-grid`：`repeat(auto-fill, minmax(196px, 1fr))`）：列数随窗口宽度适配，同行卡片等分撑满整行、不留尾空；固定 208px + wrap 的实现已废弃（放不下时右侧留大空）
- 左 3px 指示条：已指派到某显示器 = accent；失效 = danger；未指派 = 无
- 名称（13px primary，超长省略）+ 右侧角标（类型 `VIDEO/SHADER/WEB/GIF/PHOTO` + 来源 `WE`）
- meta 行（12px secondary，tabular）：分辨率 · 时长/帧率 · 指派目标（"→ 主屏"）

**交互**：

| 动作 | 行为 |
|---|---|
| 悬停卡片 | 预览自动播放（视频抽帧动图 / shader 定时截图序列；实现见 §6 spike）；已指派时**对应真实显示器边缘出现 2px accent 描边**（signature，见 4.4） |
| 单击 | 选中（accent/soft 底），状态条显示该卡片 meta 详情 |
| 双击 / `↵` | 设为**主显示器**壁纸，托盘气泡确认 |
| 右键 | 菜单：设为壁纸 →（子项：主屏/副屏/全部）· 打开所在目录 · ── · 从库中移除（红字，二次确认内联在菜单项里展开；local 拷贝条目连库内目录一并删除，WE/url 只断引用，见 §7。「查看详情」已于 0.1.1 移除——只是重复卡片上已有的三条信息） |
| **拖拽卡片 → 显示器页拓扑** | 直接指派到目标屏（跨页签拖拽；signature 交互） |
| 拖入文件 | 窗口任意位置接受 mp4/webm/gif/webp/html/glsl，导入+选中+气泡；不支持类型 → 状态条红字说明原因（HEVC 提示装扩展、mkv 提示转封装） |
| 点击 [+ 导入] | 弹出锚定菜单（单一「新增内容」入口）：**导入文件…**（打开文件对话框，与拖拽同路径）/ **从 URL 导入网页…**（打开 URL 小窗）。主路径零层级；菜单项语义 = 把新内容弄进库 |
| 搜索 | 标题/标签模糊匹配，即时过滤，`Esc` 清空 |

**筛选条**：单选段控件；`WE` 筛选仅在已导入 WE 条目时出现（无扫描——WE 只由用户主动导入）。

**空状态**（区分三种，按「库空? × 搜索词? × 筛选后空?」分派）：
- *首启未导入*（库为空，无论有无搜索词）：居中插画位（简线风格）+「把第一张壁纸拖进来，或 [导入文件] / [浏览内置样例]」（两个真按钮，不是死链接）
- *搜索无结果*（库非空 + 搜索词非空 + 筛选后空）：「没有匹配"xxx"的壁纸 · [清除搜索]」
- *筛选为空*（库非空 + 无搜索词 + 筛选后空；2026-10-07 补）：
  标题「还没有 {label} 壁纸」（label = 类型名或 WE）；WE 筛选附出路描述
  「导入时选择 Wallpaper Engine 的 project.json，即可以零拷贝引用进库」；
  动作 = [查看全部壁纸]（切回「全部」筛选）——无搜索可清，不放 [清除搜索]

**错误状态**：失效卡片信息条红字 `文件已移除`，预览区降级为灰底问号图标；右键菜单"从库移除"置顶。**预览区永不白屏。**

> **2026-10-07 变更**：新增远端网页条目（origin=`url`）。
> - 入口收敛（同日两步：先加 🔗 独立钮，经工艺复查收敛为**单一「+ 导入」菜单钮**——
>   图标幽灵钮与带字钮并排重量失衡、双入口语义重复、tooltip 依赖可发现性差；
>   反目标「模态优先」亦不允许再加独立窗体入口）。URL 小窗保留为菜单项落点，
>   粘贴 https 地址 → 导入；缺 scheme 自动补全，无效地址红字内联提示
> - 卡片 meta 行显示来源域名（如 `louie.co.nz`）；类型角标仍为 `WEB`
> - 右键「打开所在目录」置灰（远端条目无本地目录）
> - 安全边界：仅 https；页面运行在宿主页沙箱 iframe 内（无顶页导航/弹窗/表单）；
>   暂停/降帧/光标桥为 best-effort（远端页面不监听则不配合，自动暂停仍会盖住画面）


**沙盘（画布）**：
- 按**工作区坐标等比铺排**：全部屏的包围盒适配画布（留边距、居中），保留物理相对位置；单屏时居中一块大屏（宽度上限约 0.6 画布宽，避免顶满）。
- **屏幕小像 = 纯屏幕**，不再是塞满控件的卡片：屏自身宽高比（非一律 16:9）、当前壁纸预览 cover 铺满（播放中=动态，暂停=定格）、hairline 边框 + 偏移软投影、底部黑色渐变托底放 名称+分辨率（白字，任何壁纸上可读）、左上状态胶囊（深色半透玻璃：状态图标+文案）。
- 未指派：hairline 虚线边 + muted 底 + 居中「＋ 选择壁纸」（点击跳库页）。
- 交互：悬停小像 = 投影抬升；悬停库卡片 → 对应小像 **2px accent 描边**（signature 双向指认）；点击小像 = 选中（详情条随之切换）；**拖拽库卡片到具体屏上放手 = 指派**（dashed accent 描边投放态）。

**详情条（画布下方，固定高）**：
- 左：屏短名 + 「主屏」角标 + 分辨率（tabular）+ 状态（图标+文案，与托盘一致）+ 第二行 11px 备注「标识取自 EDID · 重新接入自动恢复」。
- 右：`[更换]`（跳库页）`[暂停/恢复]`（真源 = 引擎 pause_one）+ FPS 下拉（60/30/15/5）。控件恒定尺寸——**不再塞进小像**（v1 卡片在 0.125 缩放下控件不可用，是本次改版核心动因）。
- 未指派屏：右侧只有 `[选择壁纸]` 主按钮。

**状态处理**：
- 拔出已指派的显示器 → 小像消失，横幅提示「副显示器已断开，其配置已保留，重新接入自动恢复」；库卡片上该指派角标变灰
- 全屏暂停/电池暂停 → 状态胶囊如实显示（`⏸ 全屏应用中`），与托盘角标一致
- 无显示器：沙盘居中空态（简线图标 + 「未检测到显示器」+ [重新检测]）

### 4.7 软件更新（2026-10-11 新增）

技术栈非 Tauri（GPUI + wry，见 AGENTS.md），无官方 updater 插件可引；更新子系统自建
（`crates/app/src/update.rs`）。v1 交付形态 = **下载官方安装包 + 交由系统安装**
（dmg 挂载 / setup.exe 运行），**不做静默自替换**：ad-hoc 签名 + 无 Sparkle/Winsparkle
基建，自替换的失败模式（半写入损坏、签名失效、失败无法回滚）远超其收益。

**检查策略**

- 数据源：GitHub Releases `…/repos/zhanglun/gesso/releases/latest`（正式发布，
  draft/prerelease 自动排除）；`tag_name` 去前缀后按语义版本三元组比较，任一侧
  解析失败保守判定「无更新」，绝不拿坏数据提示用户
- 时机：启动 ≈15s 后静默首查 + 每 24h 一次；设置页按钮与托盘菜单可手动触发
  （手动不受 24h 抑制，但与进行中的检查/下载互斥，忙时忽略重复触发）
- 开关：设置页「自动检查更新」默认开（`settings.update_check`，仅约束自动检查）

**有更新时的通知（多层递进，各层独立，互不阻塞）**

1. 系统通知（best-effort）：macOS 走 osascript（免 bundle/签名限制，开发裸进程也能弹）；
   Windows 走 toast（依赖 AUMID，Inno 安装版有效；便携 zip 未注册时静默降级）
2. 应用内 toast（管理窗口存在时推送一条）
3. 托盘 tooltip 变为「Gesso — 新版本 v* 可用」（回到无更新态即复原）
4. 设置页「关于与更新」组常驻显示新版本号 + [查看…] 入口

**更新弹窗（与 §4.3 URL 导入同款小窗形态，标题「Gesso · 软件更新」）**

一窗承载全部状态，状态真源在更新模块全局，随引擎快照刷新（无独立定时器）：

| 状态 | 内容 | 按钮 |
|---|---|---|
| 检查中 | 转圈 + 「正在检查更新…」 | — |
| 已最新 | 「Gesso vX.Y.Z 已是最新版本」 | 关闭 |
| 发现新版本 | 新版本号 + release notes（限高滚动）+ 安装包名 · 大小 | 稍后 / 前往发布页 / **下载更新** |
| 下载中 | 进度条 + 「12.3 / 45.6 MB · 27%」（总大小未知时不确定动画） | 取消下载 |
| 下载完成 | 「下载完成」+「关闭应用后运行安装包即可完成更新」 | 关闭 / 打开所在文件夹 / **打开安装包** |
| 失败 | 红字原因 + 出路（可稍后重试，或去发布页手动下载） | 关闭 / 前往发布页 / **重试** |

- 取消下载：回到「发现新版本」态并清理 `.part` 临时文件
- 安装包选择：macOS 取含本机 arch 的 `.dmg`（无 arch 匹配退回任意 dmg）；
  Windows 优先 `<arch>-setup.exe`（安装版升级路径明确，且注册 AUMID 供通知），
  无则 `<arch>-portable.zip`
- 下载落 `<配置目录>/update/`，先写 `.part` 成功后原子改名；应用启动时清空该目录
  （残留半成品/旧安装包不跨会话保留）

## 4.8 桌面宠物 · 首次领养与托盘入口

> 生成器细节见《宠物个体生成规格.md》。

桌面宠物是 Gesso 的独立能力，不依赖壁纸。**首次领养不自动弹窗**：未领养时，用户只能从托盘菜单主动进入“开始领养”。领养完成后宠物才出现在主屏右下角。

### 托盘菜单增量

> 当前代码状态：macOS 已接入托盘“开始领养”和独立领养小窗；已支持物种选择、三候选程序化占位外观和名称选择、reroll、确认保存状态；已领养后会创建独立 AppKit 宠物窗口并在主屏右下角显示占位外观，支持拖动后识别显示器并保存屏内位置。托盘已支持显示/隐藏宠物，全屏期间会临时隐藏并在退出后恢复。窗口现已支持占位身体区域命中、透明区域穿透，以及点击/拖动分流：超过 6pt 视为拖动，300ms 内连续点击识别为摸，单击延迟确认后识别为戳；宠物设置和互动动画仍未实现。

```text
暂停全部壁纸 / 恢复全部壁纸
随机换一张
─────────────────
开始领养 / 宠物设置             ← 未领养显示「开始领养」；已领养显示「宠物设置」
显示宠物 / 隐藏宠物              ← 按当前状态二选一；未领养时隐藏
─────────────────
管理窗口…
检查更新…
─────────────────
开机自启               ✓
─────────────────
恢复系统壁纸
─────────────────
退出 Gesso
```

- 宠物组与壁纸组分隔；壁纸暂停不改变宠物状态。
- 未领养时不显示宠物窗口，不累计统计；“开始领养”打开领养浮层。
- 已领养时“宠物设置”打开宠物轻量面板；“显示/隐藏宠物”只控制可见状态。
- 关闭宠物不是删除个体；重置宠物数据只在设置页高级区域出现，不放在托盘快捷菜单。

### 领养流程

```text
选择物种 → 三候选 → 选择候选 → 确认领养
              ↑             │
              └─ reroll ────┘
```

#### 角色选择

- 当前角色页保留，即使首版只有一张「小蜡烛」角色卡；选择后进入该角色的 3 个随机个体候选。未来新增蘑菇、茶宠等角色时，只增加角色卡，不改领养状态机。
- 角色设计确认前，候选页只展示程序化占位外观和稳定生成结果。

#### 三候选

- 每轮显示 3 张候选卡，外观/名字/seed 不重复；是否保留三候选流程待首发角色设计后确认。
- 卡片展示：预览、随机生成名（中文名 + 对应英文名）、角色或外观标签；不展示内部 seed 或 `pet_id`。
- 默认没有选中态；用户必须选中一张后才能确认。
- `reroll` 替换整组三张卡，不改变物种；不设用户可见次数上限。每次只允许一个生成请求在途，生成期间按钮 disabled；当前 macOS 最小实现使用 900ms 短冷却，后续接入异步缓存生成时再以实际生成完成时间为准。
- reroll 期间按钮显示“生成中…”；完成后恢复“重新抽取”。不显示“剩余次数”或固定 3 秒倒计时；候选预览不写入正式存档。
- 程序通过 seed 组合人工图层组件生成候选，不是 AI 绘图；同一 seed 必须可稳定重建同一个个体。

#### 确认领养

> 当前 macOS app 已完成确认后的正式个体创建、版本化缓存元数据事务和安全存档写入；领养窗口已展示保存中和完成状态，成功后主屏右下角显示独立 AppKit 占位宠物窗口。正式视觉资源仍未接入；保存失败时候选页内联显示错误并提供“重试保存”。

- 选择候选后显示选中态和“确认领养”主按钮。
- 确认是不可逆的普通领养操作：确认后个体固定，不能普通 reroll 或换物种。
- 写入失败时保留当前候选并显示原因和重试入口；成功后关闭浮层、生成/缓存个体并在主屏右下角显示宠物。
- 关闭领养浮层、按 Esc 或退出 Gesso：候选全部丢弃，回到未领养状态。
- 已领养宠物窗口当前使用占位身体矩形命中，透明区域会穿透到后方应用；超过 6pt 的移动进入拖动，不生成互动；300ms 内连续点击发送 `Touch`，单击等待窗口后发送 `Poke`。正式精灵接入后应改为真实 alpha/轮廓命中，互动动画仍待接入。

#### 高级重置

- 设置页高级区域提供“重置宠物数据”。
- 二次确认文案必须明确：当前宠物、名字、统计、位置和生成缓存将被删除，且无法恢复。
- 重置成功后回到未领养状态；不会自动打开领养浮层，仍需从托盘点击“开始领养”。
- 删除或写入失败时保留当前宠物和原存档。

### 领养浮层视觉

- 使用 elevated 浮层，不打开新的管理窗口；宽度约 560px，三候选横向排列。
- 顶部显示步骤标题和关闭按钮；底部为“重新抽取”次按钮、“确认领养”主按钮。
- 物种卡和候选卡都补齐 default / hover / focus / selected / disabled / error 状态。
- reroll 只使用 150–250ms 的淡入/替换动效，不做老虎机式连续动画；生成耗时与替换动效分开处理。
- 候选卡预览使用低保真程序化占位图；正式精灵组件确定后替换，不改变交互结构。

## 7. 文案原则（中文）

- 直说，不拟人：「暂停全部壁纸」不是「让桌面休息一下」
- 失败文案带原因和出路：「HEVC 视频需要系统安装 HEVC 扩展（Microsoft Store 免费）」
- 数字用 tabular，单位前置：「4K · 12s · → 主屏」
- 危险操作动词精确：「从库中移除」永远不说「删除」。移除语义（2026-10-07 变更）：
  **local/builtin 拷贝条目 = 连同库内拷贝目录移入系统回收站/废纸篓（可恢复）**；
  WE 零拷贝引用与远端网页条目的源永不在我们手里，移除只断引用。
  回收站不可用则保留原地，绝不回退为永久删除。toast 不再承诺「文件未删除」
