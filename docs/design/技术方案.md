# Gesso 当前技术方案

> 本文只描述当前实现。历史立项方案、旧协议和系统桌面接管方案见 `docs/archive/`，不属于当前事实源。
> 代码事实源：`crates/app/src/`、`crates/core/src/`、`crates/app/API.md`。
> 历史立项方案见 [`docs/archive/技术方案-v0.1-立项稿.md`](../archive/技术方案-v0.1-立项稿.md)。

## 1. 产品边界

Gesso 是 Windows/macOS 动态壁纸引擎。当前支持：

- 视频、静态/动图图片、Shader、HTML/Web 壁纸；
- 多显示器独立指派；
- 全屏、电源、锁屏、空闲降帧和光标/时间数据桥；
- 用户主动导入的 Wallpaper Engine `video` / `web` 项目；
- 用户主动指定的远端 HTTPS 网页壁纸。

明确不做：Linux、WE `scene`/`application`、素材下载器、Steam/工坊扫描、静默自替换升级。

## 2. 进程与模块

```text
GPUI 管理窗口 + 托盘
        │ EngineAction / snapshot_ui
        ▼
SessionManager ── AppState / 配置 / 库
        │
        ├─ pin/       原生壁纸窗口与显示器拓扑
        ├─ bridge/    光标、全屏、电源、时间、锁屏
        ├─ protocol/  gesso:// 资源协议 + 回环 HTTP 媒体服务
        ├─ capture/   缩略图与悬停帧采集
        ├─ thumb/     抽帧调度
        ├─ update/    应用自更新（GitHub Release 静态 latest.json 清单检查）
        └─ desktop_bridge.rs
                     静帧供给 + macOS 重配过渡窗
```

`gesso-core` 是纯领域层，负责 `ContentSpec`、配置、库清单、`Fit` 和状态机；`gesso-app` 负责 UI、会话、平台和 IO。UI 只能调用 `crates/app/API.md` 规定的接口。

## 3. 窗口模型

壁纸窗口不是 GPUI 窗口：

- macOS：AppKit `NSWindow`，图标层下、全空间、点击穿透；视频使用 `AVQueuePlayer` / `AVPlayerLayer`；其他内容使用宿主页 WebView。
- Windows：Win32 `WS_POPUP`，挂到 Explorer 的 WorkerW 图标层之下；先 `SetParent`，后创建 WebView2；视频使用 Media Foundation + DXGI flip-model swapchain。
- 管理窗口和托盘由 GPUI 管理。
- 退出、移除和“恢复系统壁纸”只拆除 Gesso 自己的窗口。运行时不写系统桌面。

## 4. 显示器重配

拓扑事件只递增 epoch，不在系统回调中做窗口操作。引擎心跳进入去抖和收敛：

1. 事件触发即时 stale sweep；
2. 几何已过时的真实壁纸窗先隐藏；
3. macOS 若已有当前条目的预解码静帧，则创建同 pin 层的 AppKit 过渡窗；
4. 拓扑跨采样稳定后，重新施加窗口层级和几何；
5. 真实壁纸窗点亮后撤除过渡窗。

过渡窗是 Gesso 自己的窗口，不是系统桌面壁纸。日常指派和随机切换不触碰系统桌面。旧版本遗留的系统桌面桥接帧只在启动时清理一次。

显示器 ID：macOS 优先使用 EDID vendor/model/serial 三元组；无 EDID 时回落 CGDirectDisplayID，同身份多屏追加 CGID 消歧。Windows 使用平台显示器身份。唤醒或重连后按几何平移承接既有指派。

## 5. 内容管线

```text
LibraryEntry
  ├─ video  → 原生视频窗口
  └─ image / shader / html
       → ContentSpec
       → gesso://host/index.html?spec=...
       → sandboxed wallpaper WebView
```

- `gesso://host` 提供共享宿主页；`gesso://library/<entry-id>/...` 提供本地资源；WE 只读路径为 `gesso://steam/<entry-id>/...`。
- 视频媒体走本机回环 HTTP，支持 Range；不走自定义协议媒体管线。例外：Windows 原生视频窗直读本地文件（不与回环服务耦合），回环 HTTP 服务的是 webview 媒体（双平台）与 macOS 原生视频窗。
- 内容类型、扩展名、MIME 和缩略图策略以 `gesso_core::content` 为单一事实源。
- 图片源保留原扩展名；HTML 主资源固定为 `wallpaper.html`。
- 静态图片缩略图直接引用源文件；其他类型使用真实内容采集缩略图和悬停帧。

## 6. HTML 壁纸安全契约

HTML 壁纸运行在 `sandbox="allow-scripts allow-same-origin"` iframe 中：

- 可以加载允许的同源子资源并使用同源 `fetch`/`XHR`；
- 不能访问宿主页、Rust IPC、顶层导航、弹窗和表单逃逸；
- 远端网页只在用户主动导入后载入，仍受沙箱和 CSP 约束；
- 暂停/恢复通过 `postMessage`，`fps_cap` 对 HTML 只是建议值。

内容被视为不可信代码。协议只读、路径必须在条目目录内，并使用不可猜的条目 ID。

## 7. 系统数据桥

当前实现通过轮询和引擎命令向内容提供：

- 光标位置和按键状态；
- 时间；
- 电源/电池；
- 全屏应用；
- 锁屏状态；
- 空闲状态。

Rust 通过 `HostCommand` 和 `evaluate_script` 驱动 `window.__gesso`。天气设置当前只是 UI 占位，不是已实现的数据桥。

## 8. 性能与省电

- 视频使用平台原生呈现，避免 WebView 跨进程呈现交接抖动；
- 视频媒体服务对不超过 256MB 的条目提供内存直供；
- 空闲五分钟降到 5fps，有输入后恢复；
- 全屏和电源策略由状态机控制；
- `GESSO_VIDEO_DIAG=1` 帧率探针仅覆盖 webview 播放，原生视频窗暂无帧率统计；
- 过渡静帧后台生成和解码，主线程只负责 AppKit 窗口创建。

## 9. 锁屏快照同步（2026-11-07 立项；Windows 2026-11-08 实现，macOS 2026-11-09 实现）

交互规格见设计文档 §4.8/§4.8.1。本节为 Windows 实现要点；macOS 实装（静帧
+ 多桌面跟随）与扩展路线 A 的搁置决定见 §10。

技术要点：

**API 与绑定**：`Windows.System.UserProfile.LockScreen.SetImageFileAsync` /
`OriginalImageFile`。Rust 侧 `windows 0.62` 已生成全套绑定（features 增
`System_UserProfile` / `Storage` / `Foundation`）。2026-11-07 本机实测：类激活
与状态读取成功——**API 可用性以激活测试为准**，不以物理 DLL 文件名考古为准
（WinRT 走 api-set 转发；教训随实现入工程笔记）。

**数据流（封面帧，2026-11-07 用户提案）**：入库时按主屏分辨率（上限 4K）后台
生成一张固定封面帧——`thumb_home/poster.jpg`（video/shader 走画布 JPEG 原生
编码；html/gif/webp 走 PrintWindow PNG；jpg/png 静图直接引用主文件零生成），
挂在缩略图同一条主线程串行队列（独立 4K 采集窗，一次性建毁，窗口物理尺寸直建
不做 DPI 换算）。指派/开开关 = 找到当前壁纸的封面帧 → `GetFileFromPathAsync` →
`SetImageFileAsync`（毫秒级，零抓帧；指派防抖 ≈1s）。全程不进主线程重活、
不进交互路径；写入前复查开关状态。

**兜底**：旧条目/封面生成失败 → 首次指派活窗 PrintWindow 抓一帧，存
`config_dir/lockscreen/<entry_id>.png`（按条目隔离，防 A 壁纸旧帧贴到 B；
条目移除时清理），下次直接用。

**macOS 的演变**：最初以「无公开 API」为由 no-op。2026-11-08 调查 + spike
+ 两轮检索收敛出两条候选路线（视频走系统壁纸扩展、静图走官方 API 低频写，
见 §10）；2026-11-09 路线 B（静帧 + 多桌面跟随与逐桌面还原）实装并实机验证；路线 A
（扩展注册、视频动态）M1 骨架已实施后搁置——需付费开发者签名身份（详情
见 §10 与存档 docs/archive/锁屏方案调查与路线A-M1-2026-11.md）。

**还原簿记**：首次写入前记录打开前的锁屏状态落 config——模式标志
（`ContentDeliveryManager\RotatingLockScreenEnabled`：聚焦 / 图片）+ 图片路径
（`OriginalImageFile()`，含系统默认 img100 的情况）。还原 = 按记录恢复：聚焦
走注册表回切（半公开机制，**探针定案**；不可行 → 降级「保留最后快照」），图片
模式把原路径写回。写入会把锁屏切到「图片」模式（OS 行为），还原负责切回去。

**降级矩阵（能力探测与瞬时失败分开对待）**

| 条件 | 层级 | 表现 |
|---|---|---|
| LockScreen 类激活失败（WinRT 缺失） | 能力，启动探测一次 | 不渲染开关 + 一行原因（与 §4.8/实现一致） |
| 组策略 `NoChangingLockScreen=1` | 能力，启动探测一次 | 同上 |
| 单次写入被拒（运行期） | 瞬时，无状态机 | 仅日志；下次指派照常尝试（低频动作，失败无代价） |

**实测结论（2026-11-08，原「待实测清单」已全部落地）**：① `SetImageFileAsync` 端到端写入 ✓；② 封面帧直写 + PrintWindow 兜底帧按条目隔离 ✓；③ 聚焦回切走注册表（半公开机制，探针定案可行）✓；④ 图源分辨率按主屏物理像素（上限 4K）✓。本机 4K 全链路通过（写入、聚焦回切、退出还原）。

**红线关系**：不写系统桌面（「明确不做」保持不动）；锁屏图为独立 OS 表面、
opt-in、一次性后台写——与 2026-10-13 桌面桥接被砍的结构（交互路径上的高频跨进程
投递）相反。已于 ROADMAP「明确不做」加区分行。

## 10. macOS 锁屏（2026-11-08 立项；2026-11-09 路线 B 实装并实机验证；路线 A 2026-11-10 搁置）

**实装现状（路线 B，静帧）**：官方 `NSWorkspace` API 低频一次性写——把主屏
壁纸的封面帧写上被钉窗盖住的桌面壁纸层，锁屏随之显示。多桌面跟随：开关
开着时监听桌面切换，每次切换给新桌面补写封面帧；还原按簿记「已写清单」
（`mac_lockscreen_backup.applied`）换桌面逐个清扫——写回命中才动手、清单空
才销账，退出未清完的由下次启动清理收敛。已知边界：各桌面原壁纸本不相同的
场景，还原统一恢复为打开时记录的那一张（公开 API 无法按桌面备份）。
红线豁免注记见 ROADMAP「明确不做」。代码：`crates/app/src/lockscreen.rs`
macOS imp；规格：设计文档 §4.8.1。

**路线 A（视频动态上锁屏）：已搁置（2026-11-10）**。范围曾定案为「视频专属
通道」（视频走系统壁纸扩展 = 零延迟动态锁屏；shader/网页维持钉窗管线）。
M1 骨架（构建管线 + 扩展注册 + 代理拉起）已实施并实测，卡点：扩展进程启动
即崩于 ExtensionKit 运行时，且沙盒化壁纸扩展的进程拉起受 taskgated 管——
**需要 Apple Developer Program（$99/年）+ 公证**，与「产物不签名」现状不
兼容，用户决定不投入，无限期搁置。重启条件：注册 Apple Developer Program，
或 Apple 官方开放相关机制；骨架代码与构建管线保留（`GESSO_APPX=1` opt-in，
默认不嵌发布包）。调查历史、机制对比、M1 设计与实测详情：存档
`docs/archive/锁屏方案调查与路线A-M1-2026-11.md`（不再作为事实源）。
