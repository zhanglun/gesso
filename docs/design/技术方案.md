# Gesso 当前技术方案

> 本文只描述当前实现。历史立项方案、旧协议和系统桌面接管方案见 `docs/archive/`，不属于当前事实源。
> 代码事实源：`crates/app/src/`、`crates/core/src/`、`crates/app/API.md`。
> 历史立项方案见 [`docs/archive/技术方案-v0.1-立项稿.md`](../archive/技术方案-v0.1-立项稿.md)。

## 1. 产品边界

Gesso 是 Windows/macOS 动态壁纸引擎。当前支持：

- 视频、静态/动图图片、Shader、HTML/Web 壁纸；
- 多显示器独立指派；
- 全屏、电源、锁屏、空闲降帧和光标/时间数据桥；
- 用户主动导入的 Wallpaper Engine `video` / `web` 项目；
- 用户主动指定的远端 HTTPS 网页壁纸。

明确不做：Linux、WE `scene`/`application`、素材下载器、Steam/工坊扫描、静默自替换升级。

## 2. 进程与模块

```text
GPUI 管理窗口 + 托盘
        │ EngineAction / snapshot_ui
        ▼
SessionManager ── AppState / 配置 / 库
        │
        ├─ pin/       原生壁纸窗口与显示器拓扑
        ├─ bridge/    光标、全屏、电源、时间、锁屏
        ├─ protocol/  gesso:// 资源协议 + 回环 HTTP 媒体服务
        ├─ capture/   缩略图与悬停帧采集
        ├─ thumb/     抽帧调度
        ├─ update/    应用自更新（GitHub Release 静态 latest.json 清单检查）
        └─ desktop_bridge.rs
                     静帧供给 + macOS 重配过渡窗
```

`gesso-core` 是纯领域层，负责 `ContentSpec`、配置、库清单、`Fit` 和状态机；`gesso-app` 负责 UI、会话、平台和 IO。UI 只能调用 `crates/app/API.md` 规定的接口。

## 3. 窗口模型

壁纸窗口不是 GPUI 窗口：

- macOS：AppKit `NSWindow`，图标层下、全空间、点击穿透；视频使用 `AVQueuePlayer` / `AVPlayerLayer`；其他内容使用宿主页 WebView。
- Windows：Win32 `WS_POPUP`，挂到 Explorer 的 WorkerW 图标层之下；先 `SetParent`，后创建 WebView2；视频使用 Media Foundation + DXGI flip-model swapchain。
- 管理窗口和托盘由 GPUI 管理。
- 退出、移除和“恢复系统壁纸”只拆除 Gesso 自己的窗口。运行时不写系统桌面。

## 4. 显示器重配

拓扑事件只递增 epoch，不在系统回调中做窗口操作。引擎心跳进入去抖和收敛：

1. 事件触发即时 stale sweep；
2. 几何已过时的真实壁纸窗先隐藏；
3. macOS 若已有当前条目的预解码静帧，则创建同 pin 层的 AppKit 过渡窗；
4. 拓扑跨采样稳定后，重新施加窗口层级和几何；
5. 真实壁纸窗点亮后撤除过渡窗。

过渡窗是 Gesso 自己的窗口，不是系统桌面壁纸。日常指派和随机切换不触碰系统桌面。旧版本遗留的系统桌面桥接帧只在启动时清理一次。

显示器 ID：macOS 优先使用 EDID vendor/model/serial 三元组；无 EDID 时回落 CGDirectDisplayID，同身份多屏追加 CGID 消歧。Windows 使用平台显示器身份。唤醒或重连后按几何平移承接既有指派。

## 5. 内容管线

```text
LibraryEntry
  ├─ video  → 原生视频窗口
  └─ image / shader / html
       → ContentSpec
       → gesso://host/index.html?spec=...
       → sandboxed wallpaper WebView
```

- `gesso://host` 提供共享宿主页；`gesso://library/<entry-id>/...` 提供本地资源；WE 只读路径为 `gesso://steam/<entry-id>/...`。
- 视频媒体走本机回环 HTTP，支持 Range；不走自定义协议媒体管线。例外：Windows 原生视频窗直读本地文件（不与回环服务耦合），回环 HTTP 服务的是 webview 媒体（双平台）与 macOS 原生视频窗。
- 内容类型、扩展名、MIME 和缩略图策略以 `gesso_core::content` 为单一事实源。
- 图片源保留原扩展名；HTML 主资源固定为 `wallpaper.html`。
- 静态图片缩略图直接引用源文件；其他类型使用真实内容采集缩略图和悬停帧。

## 6. HTML 壁纸安全契约

HTML 壁纸运行在 `sandbox="allow-scripts allow-same-origin"` iframe 中：

- 可以加载允许的同源子资源并使用同源 `fetch`/`XHR`；
- 不能访问宿主页、Rust IPC、顶层导航、弹窗和表单逃逸；
- 远端网页只在用户主动导入后载入，仍受沙箱和 CSP 约束；
- 暂停/恢复通过 `postMessage`，`fps_cap` 对 HTML 只是建议值。

内容被视为不可信代码。协议只读、路径必须在条目目录内，并使用不可猜的条目 ID。

## 7. 系统数据桥

当前实现通过轮询和引擎命令向内容提供：

- 光标位置和按键状态；
- 时间；
- 电源/电池；
- 全屏应用；
- 锁屏状态；
- 空闲状态。

Rust 通过 `HostCommand` 和 `evaluate_script` 驱动 `window.__gesso`。天气设置当前只是 UI 占位，不是已实现的数据桥。

## 8. 性能与省电

- 视频使用平台原生呈现，避免 WebView 跨进程呈现交接抖动；
- 视频媒体服务对不超过 256MB 的条目提供内存直供；
- 空闲五分钟降到 5fps，有输入后恢复；
- 全屏和电源策略由状态机控制；
- `GESSO_VIDEO_DIAG=1` 帧率探针仅覆盖 webview 播放，原生视频窗暂无帧率统计；
- 过渡静帧后台生成和解码，主线程只负责 AppKit 窗口创建。

## 9. 锁屏快照同步（Windows，2026-11-07 立项，2026-11-08 已实现）

交互规格见设计文档 §4.8；macOS 无公开 API，不实现（编译期 no-op）。技术要点：

**API 与绑定**：`Windows.System.UserProfile.LockScreen.SetImageFileAsync` /
`OriginalImageFile`。Rust 侧 `windows 0.62` 已生成全套绑定（features 增
`System_UserProfile` / `Storage` / `Foundation`）。2026-11-07 本机实测：类激活
与状态读取成功——**API 可用性以激活测试为准**，不以物理 DLL 文件名考古为准
（WinRT 走 api-set 转发；教训随实现入工程笔记）。

**数据流（封面帧，2026-11-07 用户提案）**：入库时按主屏分辨率（上限 4K）后台
生成一张固定封面帧——`thumb_home/poster.jpg`（video/shader 走画布 JPEG 原生
编码；html/gif/webp 走 PrintWindow PNG；jpg/png 静图直接引用主文件零生成），
挂在缩略图同一条主线程串行队列（独立 4K 采集窗，一次性建毁，窗口物理尺寸直建
不做 DPI 换算）。指派/开开关 = 找到当前壁纸的封面帧 → `GetFileFromPathAsync` →
`SetImageFileAsync`（毫秒级，零抓帧；指派防抖 ≈1s）。全程不进主线程重活、
不进交互路径；写入前复查开关状态。

**兜底**：旧条目/封面生成失败 → 首次指派活窗 PrintWindow 抓一帧，存
`config_dir/lockscreen/<entry_id>.png`（按条目隔离，防 A 壁纸旧帧贴到 B；
条目移除时清理），下次直接用。

**macOS 不做的理由**：macOS 锁屏跟随桌面壁纸，而桌面壁纸代理正是 2026-10-13
桌面桥接被砍的病根（5–16s FIFO）——在 macOS 上触碰该路径即重蹈覆辙。
2026-11-08 调查 + 本机 spike + 两轮检索收敛出两条候选路线（视频走系统航拍库
注入、静图走官方 API 低频写，见 §10）；同日立项，路线 B 实施中（§10.5）。

**还原簿记**：首次写入前记录打开前的锁屏状态落 config——模式标志
（`ContentDeliveryManager\RotatingLockScreenEnabled`：聚焦 / 图片）+ 图片路径
（`OriginalImageFile()`，含系统默认 img100 的情况）。还原 = 按记录恢复：聚焦
走注册表回切（半公开机制，**探针定案**；不可行 → 降级「保留最后快照」），图片
模式把原路径写回。写入会把锁屏切到「图片」模式（OS 行为），还原负责切回去。

**降级矩阵（能力探测与瞬时失败分开对待）**

| 条件 | 层级 | 表现 |
|---|---|---|
| LockScreen 类激活失败（WinRT 缺失） | 能力，启动探测一次 | 不渲染开关 + 一行原因（与 §4.8/实现一致） |
| 组策略 `NoChangingLockScreen=1` | 能力，启动探测一次 | 同上 |
| 单次写入被拒（运行期） | 瞬时，无状态机 | 仅日志；下次指派照常尝试（低频动作，失败无代价） |

**实测结论（2026-11-08，原「待实测清单」已全部落地）**：① `SetImageFileAsync` 端到端写入 ✓；② 封面帧直写 + PrintWindow 兜底帧按条目隔离 ✓；③ 聚焦回切走注册表（半公开机制，探针定案可行）✓；④ 图源分辨率按主屏物理像素（上限 4K）✓。本机 4K 全链路通过（写入、聚焦回切、退出还原）。

**红线关系**：不写系统桌面（「明确不做」保持不动）；锁屏图为独立 OS 表面、
opt-in、一次性后台写——与 2026-10-13 桌面桥接被砍的结构（交互路径上的高频跨进程
投递）相反。已于 ROADMAP「明确不做」加区分行。

## 10. macOS 锁屏候选方案（2026-11-08 调查 + 本机 spike，同日立项）

背景：§9 的锁屏快照同步落在了 Windows 侧，macOS 当时以「无公开 API」为由
no-op。本轮调查（两轮检索）+ 本机 spike 确认商业先例存在，结论收敛为两条可
组合的候选路线（§10.3）；余下 5 项验证（§10.4，多数需肉眼）与开发并行，
实机验证结果与本节预期不符时回改规格。

### 10.1 OS 事实（公开资料，2026-11-08）

1. **没有公开的锁屏设置 API**。检索确认至 macOS 26/27 仍如此（对照 Windows
   的 WinRT `LockScreen`）。唯一公开壁纸 API 是 `NSWorkspace` 桌面读写。
2. **锁屏没有独立表面**。本机
   `~/Library/Application Support/com.apple.wallpaper/Store/Index.plist`
   顶层只有 `AllSpacesAndDisplays` / `Displays` / `Spaces` / `SystemDefault`
   四节，无锁屏专属条目——锁屏背景就是当前桌面壁纸。Windows 侧「锁屏图是
   独立 OS 表面」的红线豁免理由在 macOS 字面不成立。
3. **商业先例真实存在，机制已有开源实证**。Backdrop 2（Cindori）、Wallper、
   Wallspace、Dynamic Wallpaper Studio、MacWall 均在 macOS 15+ 支持「锁屏播放
   自家壁纸」。开源项目 **LivePaper**（MIT，macOS Tahoe 一线）逆向了
   WallpaperAgent 与「航拍库」——macOS 自带的那些航拍视频壁纸的存放地
   （`~/Library/Application Support/com.apple.wallpaper/aerials/`：`videos/`
   放视频、`thumbnails/` 放预览图、`manifest/entries.json` 是货品目录，
   系统设置 → 壁纸读它来陈列可选的视频壁纸）。实现路径与 Cindori 文档描述的
   Backdrop 流程一致：把视频**注入航拍库**（视频文件 + 缩略图 + entries.json
   资产条目），再把壁纸 Store 各节点写成 `choice.aerials` + `assetID` 的
   linked 条目，清 Agent 缓存后重启——「系统就当它是 Apple 自带的」，桌面与
   锁屏由 OS 原生播放、不依赖应用存活。LivePaper 注释明确：
   **AllSpacesAndDisplays 全局覆盖是锁屏显示的关键**。
4. **原生零风险路径**：系统原生 HEIC 动态壁纸（Equinox/Dynamic Wallpaper
   Club 一派）桌面与锁屏天然都认，锁屏显示当前时段帧（静）。上限就是静帧，
   与 Windows 侧「锁屏只接受静态图」的结论一致。
5. 壁纸代理案底不变：FIFO 每张 5–16s、拥塞时 `setDesktopImageURL` 单次阻塞
   2s（2026-10-13 桌面桥接被砍根因，f3a89a7）。

### 10.2 本机 spike 实测（2026-11-08，macOS 27.0.1）

**Store 结构与写入行为**：活动壁纸 = `choice.image` provider + `imageFile`
类型 + 任意 `file://` 本地 URL；公开 API 的写入落在
`Spaces/<Space>/Default/Desktop` 与 `Spaces/<Space>/Displays/<当前显示器>` 两
节，`SystemDefault` 是无覆盖时的回落。**写入只落当前 Space**：壁纸按桌面
各存一份，`setDesktopImageURL` 只改「此刻活跃桌面」的条目，其余桌面不变——
多桌面跟随与还原清扫据此设计（§10.5，实机多桌面验证确认）。

**三条路的实测结果（第二轮检索后修正一处结论）**：

| 尝试 | 实测 | 修正后结论 |
|---|---|---|
| 手改 Store（Index.plist） | 运行中被文件监视器当场修复；SIGSTOP→改→−9→全新拉起仍被重建 | **非死路，本机实验有盲区**：Agent 容器还有一层缓存（`~/Library/Containers/com.apple.wallpaper.agent/Data/Library/Caches/com.apple.wallpaper.caches/extension-*.aerials/`，bmp 帧缓存），LivePaper/Backdrop 的做法是改 Store 后**清缓存再重启**才生效。第一轮实验没查 Agent 容器，误判为死路 |
| 第三方壁纸扩展 | 扩展点 `com.apple.wallpaper`（ExtensionKit）无第三方注册渠道 | **非死路，可逆向**（2026-11-09 修正）：Aerial 4.1 与开源的 Phosphene 都已实装——把播放器做成 `.appex` 扩展注册到该私有扩展点（Apple 从未公开文档），系统设置直接出现自家壁纸，桌面/锁屏/登录界面由 OS 原生渲染，零同步延迟。Phosphene 开源（`kageroumado/phosphene`，私有 WallpaperExtensionKit，macOS 26+ Apple Silicon）是路线 A 的直接参考实现；风险与航拍库注入同级（私有 API 随大版本可能断） |
| 注入航拍库 | 首轮误判「Apple 自管格式不可注入」 | **可行且已有开源实证**：LivePaper 注入 `aerials/videos/<uuid>.mov` + 缩略图 + entries.json 资产条目（`url-4K-SDR-240FPS` 接受本地 file:// URL），系统视同 Apple 自带内容 |

**公开 API 完全可用**：`NSWorkspace.setDesktopImageURL` 单次写入 **1–3s 生效**
（远好于拥塞期的 5–16s；FIFO 病根是高频排队，低频一次性写不触发），回读一致；
系统对壁纸文件**不做格式白名单**，`.mov` 同样被接受（Store 记为
`choice.image`/`imageFile`，渲染层自行判断——与社区「API 只收静图」的说法
不符，以本机实测为准，是否真播放待 §10.4 验证）。
本机 pavo（Bing 壁纸应用）每日一次写入即同款先例。还原链路同机验证通过：API
写回原文件 + 原选项（allowClipping/scaling/fillColor），Store 全节点回原状。

**Store 簿记注记**：注入路线重写 Store 时会整节点替换（LivePaper 连
SystemDefault 一起覆盖）——Gesso 实做必须**整文件备份/回写 Index.plist**，
不能只记 URL。

实验器材（3 个脚本 + Store 备份）留存 `~/spike-lockscreen-20261108/`，可直接复跑。

### 10.3 候选路线（历史调查；路线 B 已实装，路线 A 范围与机制 2026-11-09 定案）

**路线 A（视频动态上锁屏）**——机制 2026-11-09 定案为**壁纸扩展注册**
（Aerial 4.1 / Phosphene 同款，见下方「范围决定」与「spike 实测」）；最初
候选机制为航拍库注入（Backdrop/LivePaper 同款，私有机制），降为备选：

1. 视频 → `aerials/videos/<uuid>.mov` + `aerials/thumbnails/<uuid>.png` +
   entries.json 资产条目（`url-4K-SDR-240FPS` 接受本地 file:// URL；schema
   见 LivePaper `AerialsInjector.swift`，categories/subcategories 各字段为
   `WallpaperAerialsCore` Codable 必填）；
2. Store 各节点写 `choice.aerials` + `Configuration={"assetID": uuid}` 的
   linked 条目——**AllSpacesAndDisplays 全局覆盖是锁屏显示的关键**（LivePaper
   注释原话）；
3. **清 Agent 缓存** + 重启 WallpaperAgent（缓存目录：
   `~/Library/Containers/com.apple.wallpaper.agent/Data/Library/Caches/com.apple.wallpaper.caches/extension-com.apple.wallpaper.extension.aerials/`）；
4. 效果：系统设置 → 壁纸出现自有分区，桌面与锁屏由 OS 原生播放视频，
   **不依赖 Gesso 存活**；
5. 还原：entries.json 移除条目 + 删视频/缩略图 + Store 整文件回写 + 重启。

风险：私有 schema（linked 条目、Agent 缓存布局、修复行为）随大版本变化，
必须按「随版本可能断、断了静默降级」设计；簿记 = 整份 Index.plist 备份。

**路线 B（封面帧静图）：官方 API 低频写**——本机已验证：指派/开开关 =
`setDesktopImageURL(封面帧, 主屏)` 一次性后台写（1–3s 生效）；四路还原
（释放/退出/移除/启动清理，簿记 = 原壁纸 URL + 缩放/裁剪/底色选项；启动
清理照抄 f3a89a7 旧桥接先例）。与被砍桥接的高频交互路径结构相反。

**组合**：静图类（jpg/png 静图与 shader/html/web 的封面帧）走 B；视频类走 A
（锁屏可动）。红线：两条路线字面上都触碰「运行时永不写系统桌面」（B 改桌面
壁纸选择，A 经扩展机制由 OS 渲染桌面并写入选择记录），须与 Windows 侧同款
显式豁免注记——低频、一次性、opt-in、非交互路径；B 写入的桌面层被 Gesso
钉窗盖住，平时不可见。

**路线 A 的实现机制二选一（2026-11-09 更新）**：① 航拍库注入（LivePaper
同款，原定）；② 壁纸扩展注册（Aerial 4.1 / Phosphene 同款，见 §10.2 修正——
私有 WallpaperExtensionKit，OS 原生渲染桌面/锁屏/登录界面，零同步延迟，
Phosphene 开源可参考）。**已定案：② 扩展注册**——spike 验证注册可行（见
「spike 实测」），① 降为备选。

**范围决定（2026-11-09，用户拍板）**：路线 A 采用「视频专属通道」——只有
视频类壁纸走系统扩展（锁屏动态视频、零延迟），shader/html/web 维持现有钉窗
管线（锁屏走路线 B 静帧）。理由：烘焙成循环视频对实时内容是功能倒退（时钟
错时、鼠标交互丢失、循环接缝可见），不再纳入范围。连带设计约定：
- 指派视频壁纸 = 不建钉窗，改为设置扩展 choice；指派非视频 = 现行为不变
- 双管线按显示器并存：部分显示器视频（扩展）、部分显示器 shader（钉窗），
  Store 按显示器记录隔离（Phosphene 解析器已验证支持）
- 托盘暂停/帧率控制对扩展内容暂不生效（扩展自带遮挡暂停/电池策略），
  作为已知差距写入规格
- 版本下限 macOS 26+；旧系统视频自动回落钉窗管线
- 红线注记：指派视频 = 经系统官方扩展机制由 OS 渲染桌面（用户主动指派即
  opt-in）；Store 写入低频一次性；恢复系统壁纸 = 移除 choice + 整文件回写
- M1 先行：协议骨架移植（系统设置可见 Gesso 条目）+ 代理拉起握手验证

**扩展注册机制的实现要点（读 Phosphene 源码 + REFERENCE.md，2026-11-09）**：
`.appex`（Info.plist `EXExtensionPointIdentifier = com.apple.wallpaper`）随
App 注册；指派 = 改 Store choice 的 Provider；扩展跑在系统 WallpaperAgent
进程里接 XPC（acquire/update/invalidate/snapshot），在远程 `CAContext` 上用
`AVSampleBufferDisplayLayer` 手动喂帧（AVPlayerLayer 在远程上下文静默失败）；
主程序与扩展靠「扩展沙盒容器共享目录 + Darwin 通知」通信。已知坑：XPC 请求
结构无 SDK 头文件靠反射解析、快照编码器需 swizzle 防锁屏灰屏、Agent 死锁
自愈、循环帧时间戳手动管理。

**spike 实测（2026-11-09，本机 macOS 27）**：① **未公证可行**——手工构建的
.appex（ad-hoc 签名，plist 与 Apple 自家 WallpaperAerialsExtension 同构，仅
EXAppExtensionAttributes→扩展点声明）成功进入 pluginkit 注册表；真正的门槛
是 **App Sandbox entitlement**（无沙盒时 pkd 日志明拒："plug-ins must be
sandboxed"，与签名无关）。「产物不签名」的发布现状不用为路线 A 破例（分发维持现状，不做专项验证——
2026-11-09 产品决定）。
② 手写 Store choice（Provider=扩展 bundleID）无法触发代理拉起扩展——
Configuration 是私有 schema，手工构造不解析，活跃空间的注入会被代理修掉；
真实入口 = 系统设置 → 壁纸（代理经 XPC 向扩展要内容目录，用户在那里选），
需实现完整 choices/settings 协议（Phosphene WallpaperXPCHandler.swift 790
行为参考）。③ 非视频内容的渲染方案（Phosphene 源码定案）：shader = 把 WE
shader 管线用 GL-on-Metal 重实现、离屏逐帧烘焙成循环视频（带 GLSL 悬死
看门狗的独立烘焙进程）；web = 同样烘焙成视频。**（该烘焙方案已被上方
「范围决定」否决——对实时内容是功能倒退，非视频内容不走扩展；本段仅作
技术记录保留）**器材留存 ~/spike-wallpaper-extension-20261109/。
**工程量重估：签名门槛已排除，余下工作 = 完整移植 XPC 协议与渲染器（有全
开源参考，无未知数），周级专项不变。**

**产品边界**（不变）：macOS 锁屏本就显示用户原壁纸，本功能的增量是「锁屏
显示 Gesso 内容（视频或封面帧）」，小于 Windows 侧（聚焦图 → 壁纸封面帧）。
规格上仍恒取主屏当前壁纸。

### 10.4 余下验证（2026-11-09 收口：多数已作废或完成）

1. ~~锁屏跟随性（路线 B 生死题）~~ **已实机确认**（2026-11-09）：API 写入
   封面帧 → ⌃⌘Q → 锁屏显示封面帧；多桌面场景写入只落当前桌面，跟随与
   清扫策略见 §10.5；
2. ~~原位更新~~ **不适用**：Gesso 流程每次指派都重写选择，从不原位改文件；
3. ~~视频播放（API 路线）~~ **作废**：视频已定走扩展路线（§10.3 范围决定），
   不再经 API 写 .mov；
4. ~~注入复跑（路线 A 生死题）~~ **作废**：机制改为扩展注册，注册可行性已
   完成 spike 验证（见 §10.3 spike 实测 ①）；
5. HEIC 动态壁纸上锁屏显示当前时段帧还是首帧（低优先级，不影响路线决策）。

### 10.5 实施决定（2026-11-08 立项）

**路线 B 先行**：封面帧经官方 API 低频写，架构对齐 Windows 侧——同一开关
（`settings.lockscreen_sync`）、同防抖、簿记还原。交互规格见设计文档
§4.8.1。路线 A 二期：机制定案为壁纸扩展注册、范围为视频专属通道（§10.3
范围决定），M1（协议骨架移植 + 代理拉起握手验证）待排期。

**多桌面（2026-11-09 实机验证补全）**：锁屏跟随性已实机确认（封面帧写入后
锁屏显示封面帧）；单次写入只覆盖当前桌面。实装策略：开关开着时监听
`NSWorkspaceActiveSpaceDidChangeNotification`，每次切换给新桌面补写封面帧
（仍是一次性低频写）；还原按簿记「已写清单」（`mac_lockscreen_backup.
applied`，写入成功后去重追加）换桌面逐个清扫，公开 API 无法按桌面备份，
各桌面原壁纸不同的场景统一恢复为打开时记录的那张（已知边界）。

代码落位：`crates/app/src/lockscreen.rs` macOS imp（对齐 Windows imp 的
公共签名）+ `crates/app/src/capture.rs` macOS 封面帧生成（对齐 Windows
PosterJob）+ `crates/core/src/config.rs` macOS 簿记结构。红线豁免注记已随
本立项写入 ROADMAP「明确不做」。

### 10.6 路线 A M1 设计与计划（2026-11-09 定稿）

**M1 目标（可验收）**：把一个最小可运行的 Gesso 壁纸扩展在本地/手动 CI 构建
中跑通注册与握手链路，为 M2 视频渲染铺路。非目标：真实视频渲染（M2）、播放
策略、非视频内容、Gesso 主程序任何 UI 变更、分发签名专项验证（维持产物不签名
现状，已由产品决定）、进入正式发布包（半成品扩展对用户可见，M3 验收后才
默认嵌入）。

**验收标准**：
1. `pluginkit -m -p com.apple.wallpaper` 列出 `com.gesso.dev.wallpaper`；
2. 系统设置 → 壁纸出现「Gesso」分区与一个占位条目；
3. 选中占位条目 → 扩展日志记录 acquire 到达（M1 回错误不渲染，渲染是 M2）。

**架构设计**：
- 语言/进程边界：扩展 = Swift `.appex`（无 Xcode，`swiftc` 直接编译——spike
  已验证 CommandLineTools 足够，CI runner 自带完整工具链）；主程序保持 Rust。
  通信 = 扩展沙盒容器共享目录 + Darwin 通知（Phosphene 模式，M1 暂不用）。
- 源码落位：`crates/app/swift/wallpaper-extension/`（Swift 源 + Info.plist）。
- 打包：`packaging/macos/build_app.sh` 增加 `GESSO_APPX=1` 开关：开启时编译
  .appex 并嵌入 `PlugIns/`，默认不嵌（半成品扩展对用户可见是坏事：系统设置
  选中后桌面/锁屏为错误状态）；M3 验收后改为默认开启。appex 以
  `--entitlements`（App Sandbox）随 bundle 现有 ad-hoc 流程重签。**每次重新
  组装 bundle 后必须 `lsregister -f`**：WallpaperAgent 会缓存已删除扩展的
  路径（Phosphene 文档踩坑：重装后壁纸卡死/灰屏，需重注册 + 重启代理）。
- 扩展 bundle id：`com.gesso.dev.wallpaper`（宿主 `com.gesso.dev`）。
- 移植范围（Phosphene → Gesso）：XPC 接口白名单配置 + 全协议导出的桩处理器
  + 调用方校验 + 日志；**系统设置分区可见的关键**是设置视图模型返回，需移植
  其对私有 `WallpaperSettingsViewModelsXPC` 的 Mirror 反射解析。主程序 M1
  不改：appex 未被选中时不激活，零风险入库。

**计划（半天粒度）**：
- D1 上午：Swift 构建脚本 + bundle 嵌入 + 本地 pluginkit 收录（复刻 spike）；
- D1 下午：协议骨架移植，WallpaperAgent 拉起验证（日志可见握手）；
- D2：设置视图模型移植（Mirror 解析私有结构），系统设置分区可见；
- 缓冲 +1 天：私有视图模型字段解析失败时逐字段调试。

**M1 专属风险**：
- 私有视图模型 schema 解析失败 → 分区不显示：缓解 = Phosphene 源码逐字段
  对照 + 逐字段 dump 日志；
- WallpaperAgent 对占位条目 acquire 失败的反应（是否下架分区）→ 观测点；
- macOS < 26：`WallpaperExtensionKit` 不存在/行为不同，appex 休眠无副作用
  （Gesso 主程序 `LSMinimumSystemVersion` 仍为 12.0，不受影响）。
- 分发签名：维持产物不签名现状，不做专项验证（2026-11-09 产品决定）；
  用户端遵循现有未签名安装流程即可。

**M2 必答问题（M1 不做，先记录防遗忘）**：
1. 指派体验：视频壁纸的选中大概率需经系统设置（程序化选中的客户端 API 是
   未知数）——与「双击卡片即指派」的落差如何处理，M2 初期调研定案；
2. 「联动（实验）」开关对扩展内容的语义：扩展壁纸锁屏常开（系统在播），
   现有开关的「关闭恢复原设置」管不到它——产品语义需定义；
3. 卸载/更新清理：用户删除 Gesso 后，系统残留的扩展选择如何收场。
