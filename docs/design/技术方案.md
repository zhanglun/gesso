## 1. 项目概述

### 1.1 目标

| # | 目标 | 度量 |
|---|------|------|
| G1 | Windows / macOS 双平台把动态内容钉到桌面图标层之下 | 两平台截图 + 全屏应用自动暂停 |
| G2 | 四种内容类型统一渲染：video/GIF/WebP、WebGL2 Shader、HTML、系统数据联动 | 每类型至少 3 个样例壁纸 |
| G3 | 多显示器独立指派，稳定显示器 ID | 拔插显示器后配置不错乱 |
| G4 | 性能与电源达标 | 空闲场景 GPU <5%，视频壁纸 CPU <5%；电池模式可暂停；全屏应用 0 开销 |
| G5（远期） | 只读导入用户已订阅的 Wallpaper Engine 创意工坊素材 | video/web 类型直接可用，scene 类型可解析 |

### 1.2 非目标（明确不做）

- **Linux 支持**（v1）。KDE/GNOME/X11/Wayland 四线作战，投入产出比最差。架构上预留 `pin` 平台 trait，不做实现。
- **内容商店 / 下载器**。不做 WE 素材再分发，只读本机已订阅内容（法律红线，见 §8.5）。
- **壁纸编辑器**。v1 只做"消费"，不做"创作"。
- **`application` 类型 WE 素材**（原生 exe），安全模型不允许，macOS 也无法运行。
- **mpv / 自研视频渲染管线**。接口预留（Renderer trait），仅当 webview 硬解被证伪才启动。

### 1.3 竞品与可抄作业清单

| 项目 | 平台 | 技术栈 | 对我们的价值 |
|------|------|--------|--------------|
| Wallpaper Engine | Win | C++/CEF | 商业标杆；素材格式（§8）的事实标准 |
| Lively（基本停滞） | Win | C#/WPF | **WorkerW 贴壁代码直接抄**，mpv 嵌入参考 |
| Plash（已闭源） | macOS | Swift | **NSWindow 贴壁参数抄其 MIT 历史版本**（当前仓库已无源码，引用需锁定闭源前的最后 commit）；其 DeactivateOnBattery 偏好项佐证了电池暂停特性 |
| Hidamari（停更） | Linux | GTK | 仅参考 |

## 2. 技术选型

### 2.1 总栈

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | **Tauri 2.x** | 体积 ~10MB；多窗口共享 webview 进程；Rust 核心直接写平台层 |
| 核心语言 | Rust (stable) | 系统 API（WorkerW/AppKit）绑定成熟：`windows` / `objc2` |
| 渲染 | 系统 webview：**WebView2**（Win）/ **WKWebView**（macOS） | 零额外体积，四类内容一条管线（§5），硬件视频解码 |
| 前端 | **管理窗口 = GPUI（纯 Rust，GPU 渲染）**；壁纸宿主页 = wry webview 内零依赖原生 TS | UI 与壁纸渲染是两种需求：前者 GPUI，后者只有 webview 能同时做视频/WebGL/HTML；`gpui-wry` 已解决共存 |
| WE 解包 | `pkg_parser`（Rust，repo: wqLouis/depkg） | 纯 Rust 解析 WE `.pkg`/`.tex`；fallback 见 §8.4 |

### 2.3 编解码支持矩阵（webview 沙箱内 `<video>`）

| 格式 | WebView2（Chromium 内核） | WKWebView（Safari 内核） |
|------|:---:|:---:|
| H.264 + AAC（.mp4） | ✅ | ✅ |
| HEVC/H.265 | ⚠️ 需系统装 HEVC 扩展 | ✅（Apple silicon 硬解） |
| VP9 / AV1（.webm） | ✅ | ✅（AV1 依芯片解码器） |
| 动图 GIF / WebP / APNG | ✅ | ✅ |
| .mkv 容器 | ❌ | ❌ |

结论：覆盖壁纸场景 >99% 的内容（mp4/webm/gif）。不支持的格式 → 导入时提示转码（v1 直接拒绝并说明，不做内置转码）。

## 3. 总体架构

（见 [01 · 系统架构图](01-系统架构.architecture.html)）

### 3.1 分层

```
┌─ 前端层（系统 webview 内）───────────────────────────────┐
│  管理窗口（全 IPC 权限）      壁纸宿主页 × N（零 IPC 沙箱）  │
├─ Tauri 命令层 ──────────────────────────────────────────┤
│  #[tauri::command] set_wallpaper / import / scan_workshop / …（§3.6）│
├─ Rust 核心服务 ─────────────────────────────────────────┤
│  会话管理器（状态机） 内容库  事件桥（光标/时间/电池→JS）    │
│  WE 适配器（workshop 扫描 / project.json / depkg）        │
├─ 平台贴壁层 `trait DesktopPinner` ──────────────────────┤
│  Windows: WorkerW 挂载        macOS: NSWindow 压层       │
└─────────────────────────────────────────────────────────┘
```

### 3.2 进程与窗口模型

- **单进程双轨窗口**（M1.5 定稿）：托盘 + 管理窗口 = GPUI 窗口；**壁纸窗口 = 纯 AppKit/Win32 自有窗口 + wry webview 直挂**（不经 GPUI 窗口管理、gpui-wry 不参与壁纸路径——GPUI 窗口协调器与桌面级全屏窗口几何必然冲突，见 SPIKE-REPORT M1.5）。两者同跑一个事件循环。多壁纸窗口的 webview 共享同一浏览器进程（WebView2 同 user-data-dir；WKWebView 同进程池），内存不是 N 倍。
- **窗口不抢焦点**：Windows 加 `WS_EX_TOOLWINDOW`（不出现在任务栏/Alt-Tab）；macOS `activationPolicy = .accessory`。
- **无 IPC**：管理 UI 与核心逻辑同进程——UI 直接调 `session` 模块方法（取代原 Tauri command 层）；对壁纸 webview 仍走 `wallpaper://` 协议 + `evaluate_script` 推送事件。

### 3.3 窗口权限分离（安全模型核心）

| 窗口 | Tauri capability | 网络访问 | 说明 |
|------|------------------|----------|------|
| 管理窗口 | 全部命令 + 文件对话框 | 允许 | 受信 UI |
| 壁纸宿主页 | **零 IPC**，仅接收 `emit` 事件；asset 协议只读白名单到指定素材目录 | 默认禁止 | 壁纸内容 = 不可信代码（HTML/JS），沙箱见 §7 |

### 3.4 代码组织（Cargo workspace）

两个 crate，不多不少：`gesso-core` 装所有纯领域逻辑（零平台依赖、零 Tauri 依赖，`cargo test` 秒级全量跑）；`gesso-app` 装 Tauri 壳与平台代码。core 不反向依赖 app，分层由编译期强制。

```text
gesso/
├── Cargo.toml                    # [workspace] members = ["crates/*"]
├── crates/
│   ├── core/                     # gesso-core：纯领域逻辑（无 GPUI/平台依赖）
│   │   └── src/
│   │       ├── spec.rs           # ContentSpec / WallpaperKind（§5.1 契约）
│   │       ├── config.rs         # AppConfig / 显示器→壁纸映射（serde + 热更新 diff）
│   │       ├── library.rs        # 内容库 manifest、随机条目 ID、导入登记
│   │       ├── session.rs        # 状态机：transfer(state, event) -> state 纯函数
│   │       └── error.rs          # thiserror 统一错误
│   └── app/                      # gesso-app：GPUI 应用（bin）
│       └── src/
│           ├── main.rs           # GPUI Application 入口、单实例锁、托盘、窗口生命周期
│           ├── ui/               # 管理窗口 UI —— GPUI（纯 Rust）
│           │   ├── library_view.rs   # 壁纸库：网格/筛选/搜索/导入
│           │   ├── monitors_view.rs  # 显示器拓扑与指派
│           │   ├── settings_view.rs  # 设置表单
│           │   └── first_run.rs      # 首启向导（§3.8）
│           ├── session.rs        # 会话管理器：唯一编排者（图 05）；对 UI 是内部 API
│           ├── pin/
│           │   ├── mod.rs        # trait DesktopPinner + cfg 分派
│           │   ├── windows.rs    # WorkerW（对 GPUI 窗口 HWND SetParent，M1 验证）
│           │   └── macos.rs      # objc2 改 GPUI 的 NSWindow
│           ├── bridge/           # 事件桥线程：cursor / fullscreen / power / time / weather
│           ├── protocol.rs       # wallpaper://（wry 自定义协议）：只读 + CSP + MIME + 导航闸

│   ├── gate.ts                   # RAF 门控 + 动态分辨率缩放（§5.3）
│   └── renderers/                # video.ts / image.ts / shader.ts / html.ts（统一 Renderer 接口）
└── assets/                       # 内置样例（自制 CC0）+ Shadertoy 预设纹理 + 宿主页图标资源
```

### 3.5 模块关系与线程模型

（见 [05 · 代码模块关系](05-代码模块关系.architecture.html)）

依赖规则三条：① UI → 命令 → 会话 → core 单向；② pin / bridge / protocol / we 互不 import，只被 session.rs 调用；③ core 对外仅依赖 serde/thiserror。

| 线程 | 职责 | 通信 |
|------|------|------|
| GPUI 主线程 | 事件循环：管理窗口渲染、壁纸窗口（GPUI 壳 + wry webview）生命周期、贴壁调用（macOS 硬约束：UI 必须主线程） | — |
| bridge ×N | OS 轮询/钩子（光标 30Hz、全屏/电源事件） | channel → 主线程 → `evaluate_script` 推给对应壁纸 webview，无锁 |
| 协议线程 | wallpaper:// 请求（MIME/CSP/路径白名单） | 只读文件系统 |

状态所有权：`AppState<Mutex<HashMap<MonitorId, Session>>>`，commands 层是唯一写者；宿主页与桥只消费事件。

### 3.6 内部 API（原 Tauri 命令层改为同进程函数）

管理 UI（GPUI Entity）直接调用 `session` 模块方法（唯一写入路径）：

| 方法 | 参数 | 语义 |
|------|------|------|
| `set_wallpaper` | monitor_id, library_id | 指派并按需重建该显示器会话 |
| `pause` / `resume` | monitor_id? | 缺省 = 全部显示器 |
| `import` | path | 本地导入（拷贝入库，生成随机 ID） |
| `scan_workshop` | steam_root? | 扫描 WE 工坊目录（M6） |
| `list_library` / `state_snapshot` | — | UI 拉取（GPUI Entity 缓存，由状态变更通知失效） |
| `update_settings` | settings | 自启/暂停策略/帧率上限/天气 key |

对壁纸 webview 的推送：`session://spec`（ContentSpec）、`session://state`（状态迁移）、`bridge://cursor | time | power | fullscreen | weather`，均经 `evaluate_script`。

```rust
pub trait DesktopPinner {
    fn ensure_pinned(&self, window: &WindowHandle, monitor: &MonitorInfo) -> Result<(), PinError>;
    fn repin_all(&self) -> Result<()>;   // explorer 重启 / 显示器变更 / 唤醒
}
```

cfg 分派（`#[cfg(windows)]` / `#[cfg(target_os = "macos")]`；Linux 留空实现返回 Unsupported，对应 §1.2 非目标）。错误约定：core 返回 thiserror 枚举；app 层命令错误统一 `{code, message}` JSON；宿主页永不 panic——加载失败走静态图回退（§9）。

### 3.7 界面与交互设计

完整规格独立成文并冻结：**[界面与交互设计.md](界面与交互设计.md)**（v1.0，模式 Operate）。要点：托盘常驻 + 左键快速面板（高频操作的家，换壁纸两击）；主窗口三页签（壁纸库 / 显示器 / 设置），880×600，轻量工具定位（v1 无标签 / 收藏 / 轮换 / 批量）；跟随系统双主题、中性灰阶、单一强调色（只做主操作 / 选中 / 状态）；中文默认 + 文案 key 化预留 i18n；signature 交互 = 拖拽卡片到显示器拓扑指派 + 悬停卡片时真实显示器边缘描边确认。产品事实固化于 [PRODUCT.md](PRODUCT.md)。

### 3.8 状态管理

状态分三域：

| 域 | 方案 | 说明 |
|----|------|------|
| 持久状态（唯一真源） | `AppState`（GPUI Global）+ 配置文件 | UI 永不持有持久副本 |
| 管理窗口 UI | **GPUI Entity 模型（内建响应式）**：`LibraryModel` / `MonitorMapModel` / `SettingsModel` 三个 Entity 包裹 core 类型，`cx.observe` 驱动重绘；会话变更由 `session` 主动 `notify` | 不引入任何额外状态库 |
| 壁纸宿主页 | 无 store：当前渲染器实例 + ContentSpec 两个模块级变量 | 事件进 → Renderer 接口调用 |

数据流单向：UI 操作 → `session` 方法 → 变更 `AppState` → notify 相关 Entity → GPUI 重绘。**不做乐观更新**——壁纸指派的失败必须走 Rust 的静态图回退链。

## 4. 平台贴壁层设计（全项目唯一硬骨头）

### 4.1 Windows：WorkerW 挂载（成熟，抄 Lively）

```rust
// pin/windows.rs 伪代码
let progman = FindWindowW(w!("Progman"), None)?;
// 0x052C：让 Explorer 生成 WorkerW 层（壁纸层），图标仍在 SHELLDLL_DefView
SendMessageTimeoutW(progman, 0x052C, 0, 0, SMTO_NORMAL, 1000, &mut result);
// 遍历顶层窗口：SHELLDLL_DefView 的下一个兄弟即 WorkerW
let worker_w = find_workerw(); // EnumWindows 找 SHELLDLL_DefView → GetWindow(GW_HWNDNEXT)
SetParent(wallpaper_hwnd, worker_w);          // 正常路径
// 失败兜底：用户关闭了桌面图标时 Progman 即壁纸层 → SetParent(progman)
```

已知坑与对策：

| 坑 | 对策 |
|----|------|
| explorer.exe 崩溃重启后壁纸窗口丢失 | 监听 `TaskbarCreated` 广播消息，重钉 |
| SetParent 后多显示器定位 | WorkerW 覆盖整个虚拟桌面，N 个子窗口按各显示器物理像素各自定位 |
| DPI 混合缩放 | 清单声明 `PerMonitorV2`，一律物理像素 + 各显示器 DPI 换算 |
| WebView2 在 SetParent 后合成异常（罕见报告） | M1 验收项；若命中，壁纸窗口先创建后挂载，并开 `--webview-gpu` 实验开关回退 |

### 4.2 macOS：NSWindow 压层（参考 Plash 历史源码，M2 前置实验确认）

```text
NSWindow（通过 raw-window-handle 拿到，objc2 修改）:
  level              = -2147483604（M1.5 定稿：图标层下缘之下一档；勿用桌面图同级，
                       同层排序不可控）
  collectionBehavior = [.canJoinAllSpaces, .stationary,
                        .fullScreenAuxiliary, .ignoresCycle]
  ignoresMouseEvents = true        // 点击穿透到图标
  isOpaque / backgroundColor       // 避免透出默认桌面图
```

风险与兜底：Tauri + objc2 改 wry 窗口这条路走得人少；**精确的 level 常量未经验证**（Apple 对图标层级的公开描述含糊，必须实验确定）。Plash 已闭源——只能从其闭源前的 MIT 历史提交取参数，M0 时先 fork/存档该 commit。**M1 结束后立即插入一个 ≤100 行的 spike 分支**验证参数可用；若 wry 窗口层级改不动，fallback = bundle 一个几百行的 Swift helper 进程持有壁纸窗口（用本地 XPC/stdio 通信），架构其余部分不变。

### 4.3 显示器稳定 ID

Tauri `monitor.name()`（Win: 设备名 / mac: 显示器名）在多同型号显示器下可能重复 → **拼接 EDID/设备路径哈希**作为 key；配置迁移（换接口）提示用户确认映射。

## 5. 渲染层：壁纸宿主页（四类内容一条管线）

### 5.1 壁纸宿主页 = 一个 shim 页面

`wallpaper-host.html` 不含任何业务逻辑，只做：接收 `ContentSpec`（via `emit`）→ 按 `kind` 实例化对应渲染器 → 暴露统一的暂停/恢复/帧率接口。

```json
// ContentSpec —— 内容库与宿主页之间唯一契约
{
  "kind": "video",                       // video | image | shader | html
  "source": "wallpaper://lib/ab12/a.mp4",// 自定义只读协议，见 §7.2
  "fit": "cover",
  "fps_cap": 60,
  "audio": "muted",
  "meta": { "title": "…", "origin": "local" }  // origin: local | we-video:123 | we-web:456
}
```

### 5.2 四类内容的实现

| kind | 实现 | 备注 |
|------|------|------|
| `video` | `<video loop muted playsinline>` + `object-fit: cover` | 硬解走系统编解码器；暂停 = `pause()` |
| `image` | `<img>`（GIF/WebP/APNG 自动播放） | 零成本 |
| `shader` | WebGL2 样板渲染器；uniform 契约 = Shadertoy 子集：`iTime / iResolution / iMouse / iTimeDelta / iFrame` + 纹理通道 `iChannel0..3`（内置 Shadertoy 标准预设纹理：2D noise / RGBA noise 等） | ⚠️ 非所有 Shadertoy 作品可跑：覆盖无纹理与标准预设纹理子集，自备贴图/键盘/麦克风的作品不支持；暂停 = 停 RAF 循环；WebGPU 是 v2 升级项不阻塞 |
| `html` | `<iframe sandbox="allow-scripts">` 加载素材目录 `index.html`，注入 **WE API shim**（§8.3） | 唯一"运行任意代码"的类型，权限模型见 §7 |

### 5.3 渲染性能模型与优化

**帧预算**（内置样例，核显）：shader 60fps 时 p95 帧时间 <15ms、GPU <5%；video 靠系统硬解 CPU <5%；暂停态 0 RAF。超预算自动降档，不靠用户手动调。

优化手段按杠杆大小排序：

1. **动态分辨率缩放**（shader 类最大杠杆）：canvas 内部分辨率 ×{1, 0.75, 0.5}，CSS 拉伸铺满。帧时间 EMA 连续超预算 → 立即降一档；稳定达标 10s → 缓慢升一档。4K 全屏合成带宽（DWM 纹理上传 ~1GB/s@4K60）比 shader ALU 更贵，降内部分辨率两者同时省。
2. **FPS 门控**：RAF gate 60→30→自定义→暂停；rAF 时间戳跳帧实现，禁 setInterval；视频驱动 shader 用 `requestVideoFrameCallback`。
3. **WebGL 上下文策略**：`powerPreference: 'low-power'`（关键：high-performance 会唤醒独显，笔记本电池杀手）、`antialias: false`、`desynchronized: true`（Chromium 低延迟呈现）。
4. **RAF 路径零 DOM**：uniform 更新 + draw call，无 layout/paint；canvas 尺寸固定。
5. **空闲降帧**：光标不在本显示器 + 无音频 → fps_cap 减半。保守启发式；壁纸被普通窗口遮挡不可观测，不假装能检测。
6. **视频**：`muted + playsinline` 必须在 play() 前设置；尺寸精确匹配免二次缩放；多显示器同素材各自独立解码（webview 跨窗口无法共享解码帧，接受此成本）。
7. **HTML 壁纸的诚实限制**：无法节流第三方 JS 的 rAF——与 Wallpaper Engine 相同；只有整窗暂停（全屏/电池）这一个杠杆，这是选 web 类素材的固有代价。
8. **首帧防白闪**：窗口先设黑底再加载 webview；宿主页默认背景 #000。

观测：dev 模式叠加层显示 fps / 帧时间 EMA / 当前分辨率档；issue 模板要求附这三项。

## 6. 数据桥：系统状态 → JS

| 信号 | 采集（Rust 侧） | 推送频率 | 用途 |
|------|-----------------|----------|------|
| 光标位置 | Win `GetCursorPos` / mac `NSEvent::mouseLocation` 全局轮询 | 30 Hz | 交互壁纸（两平台图标层都会挡事件，轮询是跨平台正解；Windows 上空白桌面区域的点击会落到 WorkerW 子窗口，属免费增强可选支持） |
| 时间/日期 | `std::time` | 1 Hz | 时钟、日夜切换 |
| 电源状态 | Win `GetSystemPowerStatus` + `PowerSettingRegisterNotification(GUID_ACDC_POWER_SOURCE)` / mac IOKit `IOPSCopyPowerSourcesInfo`（Plash 的 DeactivateOnBattery 同路线） | 事件 | 状态机 §9 输入 |
| 全屏应用 | Win `SetWinEventHook(EVENT_SYSTEM_FOREGROUND)` + 前台窗矩形==显示器 / mac `NSWorkspace.didActivateApplicationNotification` + 全屏判断 | 事件 | 自动暂停 |
| 天气 | 用户填 API key（如 open-meteo 免费无 key） | 15 min | 联动壁纸（可关） |
| 音频频谱（v2） | Win WASAPI loopback / mac ScreenCaptureKit（需授权） | 60 Hz | WE `wallpaperRegisterAudioListener` 的数据源 |

事件命名空间：`bridge://cursor`、`bridge://time`、`bridge://power`… 壁纸窗口只读。

## 7. 安全模型

1. **能力分离**（§3.3）：壁纸窗口在 Tauri capability 体系中零 IPC —— 任意 HTML 素材调不到 Rust 命令。
2. **只读资源协议**：Tauri 自定义 protocol 映射到素材目录，**只允许 GET、禁目录穿越**。⚠️ 平台差异：Windows 上实际渲染为 `http://wallpaper.localhost/`，macOS 上才是真 `wallpaper://`——跨平台 origin 不同，因此**安全机制不依赖 origin 判断**，靠三条：每条目不可猜测的随机 ID、路径白名单仅限该条目目录、对经协议返回的 HTML **注入 CSP 响应头**（`default-src` 白名单），第三方 HTML 自身的 fetch/导航也被约束。HTML 壁纸只能读自己的目录。
3. **iframe sandbox**：`allow-scripts` 但不给 `allow-same-origin`，素材 JS 无法访问宿主页上下文。
4. **网络**：壁纸窗口默认禁外网（CSP `connect-src 'none'` 起步，需要联网的素材按条目白名单放行）。
5. **开机自启**只拉起应用本体，不预加载任何远程内容。

## 8. Wallpaper Engine 素材兼容（远期目标，架构从 v1 就留位）

### 8.1 素材从哪来（已核实）

- Steam 创意工坊订阅内容落盘于：`<steam>/steamapps/workshop/content/431960/<workshopid>/`（431960 = Wallpaper Engine 的 Steam AppID）。
- 每个目录含 `project.json`：`title` / `description` / **`type`（video | web | scene | application）** / `file`（入口文件）/ `preview` / `tags` 等。
- `scene` 类型的 `file` 指向 `scene.pkg`——PKG/TEX 为已逆向的私有容器格式。

### 8.2 类型支持矩阵

| WE type | 内容形态 | 我们的策略 | 阶段 |
|---------|----------|------------|------|
| `video` | mp4 直接引用 | **零拷贝直读**（库中登记引用，不复制文件） | M6 |
| `web` | HTML5 + WE JS API | 本地化渲染 + **注入 WE API shim**（§8.3） | M6 |
| `scene` | scene.pkg（贴图 .tex、时间轴、着色器） | depkg 解包 → tex→png → scene.json → 自研轻量运行时（WebGL2 重放）；先行降级：抽取 pkg 内图片资产做静态壁纸 | M7+ |
| `application` | 原生 exe | **明确拒绝**，导入时提示"类型不支持" | 永不 |

### 8.3 WE Web API shim（兼容 web 壁纸的关键）

WE 网页壁纸依赖若干全局函数/对象，宿主页在 iframe 外层注入兼容层（数据源 = §6 数据桥）：

```js
// 最小 shim 集（按 WE 官方文档逐个补齐）
wallpaperRegisterAudioListener(cb)      // ← bridge 音频频谱（v2 前给静音数组）
wallpaperUnregisterAudioListener(cb)
wallpaperRegisterPropertyListener(cb)   // ← WE 用户属性，映射到我们的素材参数
wallpaperPropertyListener = { applyUserProperties } // 同上，旧式入口
wallpaperFolder / wallpaperVersion …    // 元信息查询
```

验收：取创意工坊热门 HTML 壁纸 20 个，渲染不白屏、不报 shim 缺失 ≥ 18 个。

### 8.4 解包工具链（已核实，按优先级）

1. **`depkg`（wqLouis，已发布 crates.io，v1.1.7，❗GPL-3.0）**：纯 Rust，解析 PKGV0001 + TEX。**许可证地雷：直接 crate 依赖会传染 GPL**。集成方式二选一：(a) 以独立子进程调用 `depkg-cli`（进程边界隔离 GPL，主程序保持宽松许可证）；(b) 接受整个项目 GPL-3.0。M6 开工前定案，⚠️ 同类工具（repkg / PyPKGer）同为逆向社区产物，选型时逐一核对许可证。
2. `notscuffed/repkg`（C#）：格式逆向的原始出处，CLI 可直接作为 build 期工具兜底。
3. `WakandaO2/PyPKGer`（Python）：格式参考实现，逻辑移植源。

### 8.5 法律红线（开源 README 必须写明）

- 只**只读引用**用户本机已订阅的工坊内容；**不做下载器、不做素材再分发、不打包素材进 release**。
- 不关联、不破解 Steam；用户无 WE 时功能不可用即可。

### 8.6 导入管线

（见 [04 · WE 素材导入管线](04-WE素材导入.dataflow.html)）：扫描（或手动指定 .pkg）→ 解析 project.json → 按 `type` 路由 → video 直引 / web 注 shim / scene 解包 → 内容库登记 `ContentSpec`（`origin: "we-video:<workshopid>"`）→ 壁纸宿主页消费。

## 9. 运行时状态机

（见 [03 · 运行时状态机](03-运行时状态机.lifecycle.html)）

每显示器一个会话，状态独立：

```
Idle ──指派──▶ Loading ──就绪──▶ Playing ⇄ Paused(user)
                  │                 ⇅  ⇅
                  └─素材缺失──▶ Error   Paused(fullscreen) / Paused(battery)
Error ──重选──▶ Idle；任何态 ──退出──▶ Stopped
```

- 暂停实现分级：`RAF 停 + video.pause()`（省满载）→ 窗口不可见时进一步挂起：Windows 用 WebView2 `TrySuspendAsync`，⚠️ WKWebView 无直接等价物，只能隐藏窗口 + 停 RAF 降帧。
- 全屏/电池暂停策略可在设置中改为"降帧到 5fps"而非全停（时钟类壁纸需求）。
