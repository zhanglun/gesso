## 0. 角色共同背景

它们是**缝隙居民**：住在桌面边缘和数字缝隙里的小生命。这个称呼是正式族群称呼，但首版不主动向用户解释；它只通过角色简介、少量气泡和彩蛋露出。

它们不属于任何壁纸。壁纸是桌面上的画，宠物可以在没有壁纸的桌面上独立生活。它们偶尔能察觉电脑里发生了动静，因此会替用户表达一条简单提醒；这只是兼职能力，不改变它们首先是桌面玩具的定位。

## 1. 共同视觉方向

- 柔和现代像素风；基础精灵格约 192px。
- 轮廓清晰、颜色柔和、低闪烁；宠物颜色固定，不随 UI 主题切换。
- 猫与果冻共享动作语义，但使用各自适合形体的动作骨架；帧序、节奏、表情和短句不同。
- 角色名字在视觉稿后确定，采用有一点族群感的短名，不强行使用普通宠物昵称。
- 用户只从托盘进入首次领养；先选物种，每轮展示 3 个彼此不同、由程序基于 seed 随机生成的同物种候选，确认前可无限 reroll；生成中按钮暂时不可用，目标短冷却约 800ms–1s。
- 领养确认后由 root seed 在物种模板内生成一个固定的个体；正式存档同时保存已解析外观参数和版本信息。每台电脑首版只拥有一个已领养个体，普通流程不提供改养其他物种或重新生成；高级设置可二次确认后重置并重新领养。
- 中文名和英文名是一一对应的语言对；本机名字查重，候选使用临时 `candidate_id`，正式 `pet_id` 只在确认领养时创建；内部 ID 使用高熵随机值。
- 采用人工绘制图层组件组合，领养时离线生成并缓存完整精灵帧；不让程序自由生成未经验证的骨骼和动作。
- 首版随机名字、配色、花纹和小特征；本机名字查重，内部 ID 使用高熵随机值；无服务器时只承诺极低碰撞概率，不承诺绝对全球唯一。
- 首发素材必须是项目自有或明确授权素材。

## 2. 角色 A：安静的小猫

| 项 | 方向 |
|---|---|
| id | 暂定物种模板 `gesso.cat`；个体 id 在领养时生成 |
| 名字 | 待视觉稿后按缝隙居民命名规则确定 |
| 一句话人设 | 从桌面缝隙里醒来的小猫，喜欢找一个安静的位置睡觉；看起来总是没睡醒，但你摸它时它从来不会真的躲开。 |
| 性格关键词 | 困倦、温柔、观察、嘴硬、慢热 |
| 外形方向 | 保留圆润、矮身、易读的猫形；具体毛色、耳朵和尾巴造型由视觉稿决定 |
| 默认档位 | `quiet` |
| 行为节奏 | 慢 |
| 互动反应 | 摸时眯眼享受，戳时小幅抗议 |
| 助手彩蛋 | 偶尔看向气泡或屏幕边缘，像是先一步察觉到动静 |

### 2.1 小猫动作演出

| 语义 | 演出方向 |
|---|---|
| `idle` | 慢眨眼、张望、尾巴轻摆 |
| `walk` | 短距离慢走，不做复杂屏边动作 |
| `sleep` | 蜷睡、轻微呼吸、低闪烁睡眠提示 |
| `wake` | 迷糊抬头、伸懒腰、回到待机 |
| `poked` | 小幅惊跳，随后装作没事 |
| `petted` | 眯眼、靠近点击方向、短暂满足 |
| `notify_result` | 抬头或慢慢挥一下爪 |
| `notify_attention` | 看向用户，轻敲提示区域 |
| `notify_warning` | 耳朵竖起、警觉看向气泡 |
| `hide` | 蹲下、缩进缝隙般淡出 |

### 2.2 小猫气泡方向

首版使用短句，不做长对话树。以下为语气样例，正式双语文案在视觉稿和动作帧确定后定稿：

| 触发点 | 中文方向 | English direction |
|---|---|---|
| `welcome` | ……住这儿了。 | …staying here. |
| `poked` | 唔？ | hm? |
| `petted` | ……呼。 | …purr. |
| `sleep` | 暖和……zZ | warm… zZ |
| `wake` | 我醒着。大概。 | I’m awake. Probably. |
| `notify_result` | 有新动静。 | something new. |
| `notify_attention` | 你要看一下吗？ | you may want to look. |
| `notify_warning` | 嗯……这个不太对。 | hm… that seems off. |
| `walk_rare` | 换个地方睡。 | finding a better spot. |
| `signal_easter_egg` | ……你也看到了？ | …you saw that too? |

## 3. 角色 B：活泼的果冻生物（工作名：泡泡）

| 项 | 方向 |
|---|---|
| id | 暂定物种模板 `gesso.jelly`；个体 id 在领养时生成 |
| 工作名 | 泡泡；正式名字待视觉稿后按缝隙居民命名规则确定 |
| 名字 | 待视觉稿后按缝隙居民命名规则确定 |
| 一句话人设 | 从数字缝隙里弹出来的一小团果冻，遇到什么都想先弹一下；它会把电脑里的动静变成头顶的小信号，再兴奋地告诉你。 |
| 性格关键词 | Q弹、好奇、自来熟、撒娇、爱传话 |
| 外形方向 | 柔软的果冻/史莱姆形体；可以压扁、弹起、冒泡，但不绑定点心包装设定 |
| 默认档位 | `lively` |
| 行为节奏 | 快 |
| 互动反应 | 摸时变形冒泡，戳时弹开再弹回 |
| 助手彩蛋 | 小信号点、感叹号、气泡或短暂的提示符号；不做机器人外观 |

### 3.1 果冻生物动作演出

| 语义 | 演出方向 |
|---|---|
| `idle` | Q弹呼吸、轻晃、偶尔冒一个小泡 |
| `walk` | 短距离弹跳或滑动，不做持续漫游 |
| `sleep` | 软塌、缩成一团，气泡变慢 |
| `wake` | 弹起、抖一抖，迅速回到待机 |
| `poked` | 被戳弹开，再像果冻一样回弹 |
| `petted` | 变形、冒心或冒泡，明显表达开心 |
| `notify_result` | 开心弹一下或挥出小信号 |
| `notify_attention` | 连续小幅弹跳，敲出提示气泡 |
| `notify_warning` | 信号颜色/形状短暂变化，明显但低闪烁 |
| `hide` | 缩成小团、弹入缝隙般淡出 |

### 3.2 果冻生物气泡方向

| 触发点 | 中文方向 | English direction |
|---|---|---|
| `welcome` | 弹——新家！ | boing—new home! |
| `poked` | 咦？弹回来了！ | hey, bounced back! |
| `petted` | 再摸一下嘛！ | pat me again! |
| `sleep` | 弹不动了……zZ | out of bounce… zZ |
| `wake` | 弹——精神了！ | boing—charged up! |
| `notify_result` | 有新动静！ | something new! |
| `notify_attention` | 看一下嘛！ | take a look! |
| `notify_warning` | 呜，信号不对！ | uh-oh, strange signal! |
| `signal_easter_egg` | 啵。收到。 | pop. received. |
| `walk_rare` | 弹跳巡逻～ | bounce patrol~ |

## 4. 文案与动作纪律

- 两只宠物的事件语义一致，角色语气不同。
- `new_result` 只表达“有新动静/有新结果”，不说“成功”或“完成”。
- `needs_attention` 表达“看一下”，不替用户判断业务状态。
- `warning` 表达异常或需要留意，不伪造失败原因。
- 助手感只通过信号、气泡、观察和传话表达，不把宠物设计成机器人或通知中心。
- 气泡短、可快速读完；不在桌面常驻名字和长文。
- 中英文案一一对应；正式文案包在角色名和视觉方向定稿后落盘。

## 5. 个体生成边界

- 首次领养先选猫或果冻，再进入抽卡式候选流程。
- 每轮生成 3 个彼此不同、由程序基于 seed 组合人工图层组件生成的同物种候选；候选只存在于临时预览，确认前可无限 reroll，生成中单任务保护，目标短冷却约 800ms–1s。
- 用户确认其中一个后，才创建正式 `pet_id` 并保存 root seed、物种、名字、已解析外观参数和版本信息；缓存失败时优先使用已保存参数重建，候选取消或 reroll 不产生正式个体。新增尾巴、毛色、衣服等外观字段使用独立命名空间子 seed，不改变既有字段；已有宠物默认不自动变样。
- 每台电脑首版只拥有一个已领养个体；确认后普通流程固定，不提供改养其他物种或重新生成；高级设置可二次确认后重置全部宠物数据，再重新领养；未来多宠物升级另行设计迁移。
- 正式名字与视觉稿一起确定；生成器的名字词库应支持本机查重。
