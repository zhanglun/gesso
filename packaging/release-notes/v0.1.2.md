# Gesso 0.1.2

> 修复版本：填充模式、桌面桥接过渡窗重构（运行时永不写系统桌面），以及一批 0.1.1 反馈问题。

0.1.2 is a fix release driven by feedback after 0.1.1.

## ✨ Highlights

- **Fill modes.** Each display gains a fill setting — Fill (crop, default) /
  Fit (letterbox) / Stretch — matching Wallpaper Engine and system wallpaper
  habits. Previously non-16:9 clips were always letterboxed on macOS and
  stretched on Windows video; both platforms now share the same three modes,
  applied live without re-assigning. Thumbnails keep full-frame semantics.
- **Double-click and random-switch no longer freeze the UI.** The first
  0.1.2 build briefly rewrote the system desktop on every assignment; the
  macOS wallpaper agent queues each change (5–16 s) and a congested write
  costs ~2 s on the main thread. Gesso now never touches the system desktop
  at runtime. During display reconfiguration (wake, lid, plug, resolution
  change) a Gesso-owned transition window shows a still frame of the current
  wallpaper for the sub-second gap, then disappears once the real window is
  in place.
- **"Restore system wallpaper" now does what it says.** It clears all
  assignments and tears down the wallpaper windows, and the change is visible
  immediately; the next launch does not rebuild sessions until you assign
  again. Because Gesso no longer takes over the desktop picture, this path is
  instant — the earlier 0.1.x restore bugs (rotator apps deleting the
  recorded original, macOS 26 aerial wallpapers rendering black, slow restore
  settling) no longer exist.
- **"Random wallpaper" is actually random now** (it used to cycle in library
  order), and works again after "Restore system wallpaper" (it falls back to
  the main display when no session is left).
- **Updater fixes.** The in-app updater now follows the system proxy (as set
  by Clash / Surge / system settings) — previously a GUI-launched app did not
  inherit shell proxy variables and the HTTP client ignored the OS proxy, so
  update downloads timed out on networks that need a proxy ("os error 60").
  Environment-variable proxies still take precedence; PAC-only setups fall
  back to a direct connection. The "Retry" button works again after a failed
  download (a busy-flag leak had been ignoring every later request until
  restart), the error state is cleared when the update window closes, a
  stalled download aborts after 30 s instead of hanging, and failure
  messages now point to the release page for a manual download.
- Monitor page polish: sandbox previews follow the display's fill mode,
  hover and selection outlines no longer cross between displays, and the
  detail strip's controls were re-spaced so long dropdown entries are not
  cut off.

## 🔓 First launch (builds are unsigned)

Same as before: macOS — right-click → Open in Finder; Windows — SmartScreen →
**More info → Run anyway**. Step-by-step instructions are in the
[0.1.0 release notes](https://github.com/zhanglun/gesso/releases/tag/v0.1.0).

Windows needs the WebView2 Evergreen Runtime (preinstalled on most
Windows 10/11; it powers shader, photo and web wallpapers).

## ⚠️ Known limitations

- Windows multi-monitor pinning is implemented; hardware verification so far
  covers single-display setups.
- Static image entries (JPEG, etc.) don't have a decoded still frame yet, so
  their reconfiguration gap shows your own wallpaper for a moment (v1).
- Wallpaper Engine `video` / `web` projects are supported; `scene` and
  `application` are not (yet).
- Web wallpapers stay self-contained and offline: external iframes, top
  navigation, popups and forms are intentionally blocked.
